# 火球の構成編集と保存前プレビュー

後続の配置編集では「本体の見た目」を「弾Objectの見た目」に改称し、術者の参照項目と分離しました。素材追加後の単独表示・ギズモ操作は[攻撃部品の選択とギズモ配置](14I_攻撃部品の選択とギズモ配置.md)を参照してください。この章の動作中の判定表示は、配置用ギズモとは別です。

## 1. 今回できるようにしたこと

既存の「中距離火球」「コピー火球」「プリズムの炎の扇状連射」に、弾ごとの構成データを持たせました。新しい見本を作るだけでなく、既存攻撃を選んで、その弾の見た目・判定・軌跡・着弾を再編集するための変更です。

左側の「攻撃の構成」は、Scene内の全Objectを並べるHierarchyとは別の、攻撃データ専用の一覧です。弾の下には次の項目が並びます。

```text
中距離火球
  火球 1
    本体の見た目
    当たり判定
    飛行中の軌跡
    着弾エフェクト
  発射エフェクト 2
```

この子項目は同じ弾が使う設定です。Sceneへそれぞれ独立したObjectを置く機能ではありません。発射エフェクトは別の時刻付き命令です。判定を消しても弾の表示だけを残せます。

## 2. 操作の順序

1. 敵攻撃プレビューで炎スライムを選び、対象の攻撃を「中距離火球」にします。
2. 左の「火球 1」を選びます。右に発射時刻・弾数・速度・寿命などが出ます。
3. 「当たり判定」を選ぶと、判定ON/OFF・半径・ダメージを編集できます。
4. 「保存せずに攻撃を試す」を押します。編集中の設定を実際の攻撃ランタイムで再生します。
5. 判定球表示をONにして、再生を止めます。半径を変え、入力を離すと、自動反映ONなら同じ再生時刻まで作り直します。「変更を同じ再生位置へ反映」でも明示的に反映できます。
6. 「保存」でJSONへ書き込みます。「保存して攻撃を再生」は保存済み設定で再生し直します。
7. 「保存済みへ戻す」でファイルを開き直します。未保存の変更がある場合は破棄の確認が出ます。

弾の追加・複製・削除も一覧とInspectorから行えます。攻撃全体を別案にする場合は「この攻撃を複製して編集」を使います。

### 「単発発射数」とは何だったのか

今回の弾Inspectorでは「一度に出す弾の数」と表示します。発射時刻に一度だけ実行される命令が、何発の弾を同時生成するかです。3なら同じ時刻に3発です。3回の連射を意味しません。

間を空けて3回撃ちたい場合は、弾を複製して各発生時刻を変えます。同時発射の弾を扇状に広げるには「扇状に広がる角度」を設定します。無効チェックを外した命令は実行されません。

## 3. 保存される範囲

| 編集するもの | JSONの位置 | 意味 |
|---|---|---|
| 構成名・有効無効 | `sequence.events[].name / enabled` | 一覧の名前と命令の有効状態 |
| 発生時刻・同時発射数 | `time / count` | 何秒に何発生成するか |
| 発生位置・照準・角度 | `offset / sizeOffset / aimAtTarget / yawDegrees` など | 術者基準の配置と初期発射方向 |
| 本体の見た目 | `projectile.model / style / visualScale / appearance` | モデル、描画方式、倍率、色、炎のパラメータ |
| 判定 | `projectile.collisionEnabled / radius / damage` | 接触の有無、ワールド半径、威力 |
| 移動 | `projectile.minSpeed / maxSpeed / lifetime` | 速度の制限と弾の寿命 |
| 軌跡 | `projectile.trail / secondaryTrail` と `appearance.trailInterval / trailSpeedScale` | GPU素材参照、発生間隔、粒子速度倍率 |
| 着弾 | `projectile.impact / secondaryImpact` | 衝突時に放出するGPU素材参照 |
| 状態異常 | 攻撃全体の `combat.statusEffect` | 現在は弾ごとの独立設定ではありません |

敵の保存先は `Resources/json/enemy_attack/fire_slime.json` と `prism_slime.json` です。GPU素材自体は `Resources/json/gpu_particles/` にあり、攻撃側は名前で参照します。粒子数・発生形状・粒子の動きそのものを変えるときはGPUパーティクルのエディターで素材を編集します。

「保存せず」の再生位置、選択項目、編集履歴は攻撃JSONには保存しません。Undo/Redoはシーケンス編集用で、Scene全体やすべてのInspector項目を戻す履歴ではありません。

旧JSONも読み込めます。`projectile` がない弾は攻撃全体の既定値を引き継ぎます。個別設定がある弾はそちらを優先するので、旧設定側の半径や外観を変えてもその弾には反映されません。普段は左の弾から編集してください。

共有アセットを参照する攻撃については、現状は選択中の共有アセットを保存します。共有内容を変えたら攻撃を切り替える前に保存してください。複数の共有アセットを最後に一括保存する管理は今回の対象外です。

## 4. エディターから実行されるまで

### データ駆動と共通ランタイム

`AttackProjectileComponent` は設定だけを持ちます。`EnemyAttackProfile` のJSON変換がこの構造体を読み書きし、`AttackSequence` が発射時刻に `BulletManager::Fire()` を呼びます。本番とプレビューで弾の移動・衝突・VFXの処理を共用します。

`AttackSequenceClock` は時刻順に命令を実行し、一度実行した命令を同じ再生中に繰り返しません。無効な命令はスキップします。条件不成立で停止する設定とは別なので、無効化だけでは後続の弾を止めません。

これは「データ駆動」「イベントシーケンス」「共通ランタイム」の組み合わせです。JSONがC++を自動生成するわけではありません。発射・移動・判定というC++の共通機能を、JSONの値で組み立てます。

### 保存前プレビューはスナップショット

`PreviewDraft()` は `editableProfile_` を `draftProfile_` へコピーします。これが編集時点のスナップショットです。作り直した隔離プレビューの敵には `SetEditorPreviewProfile()`、コピー能力には `SetCopyPreviewProfile()` で渡します。どちらも内部プレビューActorだけを対象とします。

編集用データを本番の共有キャッシュへ書き込まないので、保存前の変更はJSONへ出ません。プレビュー中に値を変えたときは、入力を離して約0.15秒後にスナップショットを更新し、`SeekPreview()` の固定ステップ再生で元の時刻まで進めます。

この方式は発射済みの弾を直接書き換える方式ではありません。過去の発射から作り直すため、発射時刻・弾数・当たり判定など生成後には変更しにくい設定も比較できます。その代わり、長い時刻への再構築には時間がかかります。また乱数状態を全保存していないので、同じ時刻でもAIや粒子まで完全一致する保証はありません。

### 判定球の表示

`DrawAttackOverlay()` は実際に生存しているBulletを走査し、実際の `GetCollisionRadius()` を使って球の輪を3平面に描きます。ワールド位置にカメラのViewProjection行列を掛け、透視除算してGame View内のImGui座標へ移します。

判定ONは黄色、OFFは灰色です。実際の弾がまだ出ていない時刻、消滅した後、画面外では表示されません。これは判定確認用の描画で、輪をマウスで直接つかむギズモではありません。調整はInspectorの数値ドラッグで行います。

### 見た目と当たり判定を分離

従来は表示スケールがColliderの半径にも掛かっていました。旧形式の読み込み時と今回のJSON移行では `旧半径 × 旧表示スケール` をワールド半径として引き継ぎます。

新しい共通弾は `collisionRadiusIsWorld` を指定し、Colliderのスケール上書きを1にします。そのため表示を大きくしても判定半径は変わりません。このフラグを使わない既存の弾の呼び出しは従来の扱いを維持します。

接触判定OFFはCollisionの属性とマスクを0にします。通常の接触と移動中のSphereCastから対象が除外され、弾は寿命まで進みます。自然消滅では着弾VFXは出ません。

### 火の描画と粒子

本体の炎は既存のMaterial Type 11 / Effect Type 1へ、色・発光・広がり・境界などを渡して描画します。今回シェーダーの技法自体は変えていません。軌跡は弾の移動中にGPUパーティクルのプリセットを一定間隔で放出し、着弾時は別のプリセットを放出します。これらの素材名を弾ごとに差し替えられるようにしました。

## 5. 今回の範囲と残る部分

- 既存攻撃すべてのC++実装を置換したわけではありません。ブレス、結晶召喚陣など共通シーケンス未移行の攻撃は引き続き数値調整・観測です。
- 火球のモデルは素材一覧で選択できます。GPU素材も名前で選択できますが、全素材の画像付きカタログにはなっていません。
- 自由配置のMeshEffect、判定トラック、アニメーション、追尾トラックは既存のトラック編集を使います。今回の火球の構成と、全種類のObjectを完全に統一したScene編集はまだ別です。
- 今回の通常の弾の移動は初期照準と速度によるものです。追尾専用トラックと同じ追尾設定を全Bulletへ搭載したわけではありません。
- プリズムの外側の行動サイクル、第二形態カメラなどは既存C++です。攻撃候補の選択設定だけでAI全体を作れるわけではありません。

## 6. 検証

Development x64のソリューションビルドが成功し、通常の `generated/outputs/Development/DirectXGame.exe` を更新しました。ImGui追加部分は `USE_IMGUI` 条件に従います。Debug構成にも同じマクロがありますが、今回の全体ビルド確認はDevelopment構成です。

仕上げ後の再ビルドも成功し、最後の確認はC++再コンパイルなしで約2.7秒でした。長い日本語・長文・`%` を含む状態ラベルのImGui回帰テストも再実行して成功しています。

`tests/AttackSequenceTests.cpp` で実際の保存・読込を通し、構成名、有効状態、判定OFF、独立した半径と表示倍率、軌跡削除、着弾素材、色が保持されることを検証します。隣の弾へ設定が混ざらないこと、無効イベントが後続を止めないこと、不正な半径・速度範囲を拒否することも確認します。

既存のプリズム5発の発射時刻・位置・速度・角度の互換性テストも通しています。

実画面操作はWindows操作ツールが初期化中に終了したため未確認です。ビルドとデータテストを通した状態でも、描画・操作感を実機検証済みとは扱いません。

## 7. 火球が接触してもHPが減らないプレビュー判定の修正

弾の移動は `Bullet::Update()` のSphereCastで実際のColliderを調べます。一方、敵攻撃プレビューのダメージ処理は、以前はプレイヤーの原点と表示スケールから作った簡易球を使っていました。

プレイヤーのColliderにはローカル中心のずれがあり、描画の伸縮から独立したスケールもあります。そのため、実Colliderに接触して火球が止まっても、簡易球に届かずダメージイベントを発行しない場合がありました。

`ResolvePreviewProjectileHits()` を、実際の弾とプレイヤーの `Collider::CheckCollision()` で確認する処理へ変更しました。コピー弾のプレビューも固定半径の近似を廃止しました。属性・マスクによる攻撃対象の確認は行い、判定OFFの弾は除外します。

プレビュー標的は通常の物理応答を止めるためmaskが0です。このため `Object3d::CheckCollision()` では標的が除外されます。プレビューの明示的な命中確認ではColliderの形状照合を使います。通常プレイの衝突マスクは変更していません。

`tests/AttackPreviewCollisionTests.cpp` はstage1のプレイヤーJSONから実際の中心・形状・サイズを読み、Playerの初期判定スケール2を適用します。接触位置 `(0, 0.35, -1.60)` と半径0.6の弾で、旧簡易球は見逃し、実Colliderは命中することを確認しています。離れた弾と無効形状は命中しないことも検証します。このテストは形状判定の回帰確認であり、実画面でHPが減るまでの通し確認を代替しません。
