# 攻撃部品の選択とギズモ配置

## 1. 今回の対象

2026-10-07の改良は、術者と攻撃部品の区別、選択した部品の単独表示、画面上の配置操作が対象です。共通シーケンスに移行済みの攻撃で使います。炎スライムの中距離火球などが対象です。未移行のC++攻撃を自動で部品に分解する機能ではありません。

### 術者と生成Object

左の一覧は次の役割を区別します。

```text
攻撃全体の設定
術者（参照）: 炎スライム
生成・放出の各項目
  火球 1
    弾Objectの見た目
    当たり判定
    飛行中の軌跡
    着弾エフェクト
  選んだGPU素材
表示素材・判定・術者アニメーションの各項目
```

術者はプレビューで攻撃する敵／プレイヤーです。既存のEnemyFactoryなどで生成するActorへの参照で、今回この項目から敵のモデルは変更できません。「弾Objectの見た目」でモデルを変更した場合、変わるのは発射される物です。炎スライム自身の見た目には適用しません。

弾の子項目は同じ弾の設定を分けたものです。軌跡だけを別Objectとして自由に親子付けできる構造には、まだしていません。保存形式も従来のeventsとtracksを維持しています。

## 2. 最初に試す手順

1. 編集モードで敵攻撃プレビューを開き、炎スライムの中距離火球を選びます。
2. 左の「火球 1」または「弾Objectの見た目」を選びます。攻撃全体の再生を止め、弾の配置用Objectを表示します。
3. 右の「術者と標的を一時的に隠す」をONにすると、スライムと標的を隠して選択部品を見られます。
4. 「選択位置へカメラを寄せる」で注視位置を合わせます。これは注視点への平行移動で、素材の大きさに合わせた自動ズームではありません。
5. 「移動」を選び、中央の矢印をドラッグします。Inspectorの発生位置と同じデータを変更します。
6. 「水平回転」で発射基準の向き、「弾の表示倍率」で見た目の大きさを変えます。判定半径は別の数値です。
7. 左の「当たり判定」を選ぶと、配置位置に半径の輪を重ねます。半径・判定ON/OFF・ダメージはInspectorで変えます。
8. 「保存せず動作確認」で攻撃として再生し、発射・移動・接触を確認します。
9. 保存し、必要なら「保存済みへ戻す」でJSONから読み直します。未保存の変更は確認後に破棄されます。

配置の輪は配置ガイドです。そこで命中やHP減少は発生しません。動作確認中の判定表示とは用途が異なります。

## 3. GPU素材を追加する

1. 左の「＋ 部品を追加（素材から選択）」を押します。
2. 種類を「GPU素材の放出」にします。
3. GPU素材を選ぶと命令を追加し、その素材の配置確認に入ります。
4. 発生位置にはマーカーと部品名を描き、移動ギズモを表示します。
5. 「素材の経過時間」で一度放出した粒子の見え方を確認します。寿命より後なら粒子は消えます。見えない場合は時刻を先頭側へ戻してください。
6. 発生時刻はInspectorで別に指定します。素材の経過時間を動かしても発生時刻は書き換えません。

GPU素材の粒子サイズ・粒子数・寿命自体はGPUパーティクルエディターで変更します。攻撃のGPU放出には独立した表示倍率を保存する項目がないため、ここでは拡縮ギズモを出しません。方向指定の有効無効により、水平回転が粒子の飛ぶ向きに影響するかが変わります。

素材一覧全体の画像付きカタログは未対応です。現段階は名前で素材を選び、追加後の中央表示で確認する流れです。メッシュ頂点から発生するGPU素材は所有モデルが必要なので、この単独表示では非対応として理由を表示します。他のObjectの頂点を流用しません。

弾の「飛行中の軌跡」「着弾エフェクト」も選択した素材を単独表示します。軌跡の長い移動履歴や衝突時の反射方向まで再現するものではありません。それらは攻撃全体の動作確認で見ます。

## 4. 表示素材と時刻の編集

「表示素材（MeshEffect）」は時間区間を持つtrackとして追加します。選ぶと中央に配置し、移動・回転・拡縮を操作できます。

キーフレーム式の部品では、「編集時刻」は部品開始からの秒数です。例えば表示開始が攻撃開始の1秒後で、編集時刻が0.5秒なら、攻撃全体では1.5秒時点の姿勢を編集します。その時刻にキーがあれば更新し、なければキーを追加して時刻順に並べます。既存キーの補間方式はInspectorで設定します。

直進・追尾などの移動モードを指定した表示物は、ギズモで発射前の初期位置を編集します。配置確認でAIや追尾計算は進めません。術者アニメーションもここでObjectとして動かす対象ではなく、攻撃全体の再生で確認します。

判定trackは位置ギズモと半径の輪を出します。回転しても球の形は変わらないため、回転ギズモは出しません。半径はInspectorで編集します。親のMeshEffectがある場合は、親のキー姿勢を基準に配置を計算します。親が追尾した後の実際の位置は動作確認が必要です。

## 5. どこに保存されるか

| 操作 | 編集するデータ | 保存されないもの |
|---|---|---|
| 弾・GPUの移動 | eventのright/up/forward。JSONではoffset | 配置Objectそのもの |
| 弾・GPUの水平回転 | yawDegreesと位置維持用offset | ギズモの表示状態 |
| 弾の均等拡縮 | projectile.visualScale | 判定半径は連動しない |
| 表示・判定trackの配置 | tracks[].keysの時刻と姿勢 | Scene用Transform |
| 発射時刻・表示区間 | events[].time、tracks[].begin/end | 配置確認の時刻 |
| 術者を隠す・カメラ移動 | エディター内だけ | 攻撃JSONには保存しない |

保存先は従来どおり敵攻撃プロファイルです。共有sequenceアセットが指定されている場合はその共有内容も保存対象です。参照するGPU／MeshEffect素材自体をこの配置操作で上書きはしません。

ギズモを押してから離すまでを一回の編集として、sequenceの変更前スナップショットをUndo履歴へ入れます。取り消し／やり直しでは表示を閉じて全体選択に戻し、古い添字が別部品を指すことを避けます。戻した部品を再選択して配置を続けます。履歴はセッション内で、ファイルには保存しません。

## 6. 使用している技術と実装の流れ

### 選択状態と編集用表示

`EnemyAttackPreviewWindow.Authoring.cpp`が左の選択、右のInspector、配置確認を担当します。術者／イベント／trackを区別し、既存JSONを変更せずに画面上の役割を分けています。

弾の配置表示はSceneが所有する一時的なObject3dです。EditorInternalとして通常編集から外し、衝突属性とマスクを0にして、選択弾のモデル・見た目を適用します。選択変更や終了でSceneに削除を依頼します。本編のBulletを停止状態で共有しているわけではありません。

`GameEditorController.Viewport.cpp`からGame View内へ攻撃用のオーバーレイを描きます。この編集が選択されている間はScene用の選択・ギズモ・素材ドロップ・Sprite操作を抑止し、一つのドラッグで別エディターまで動かないようにしています。

### ImGuizmoと座標変換

ImGuizmoにカメラのView行列、Projection行列、選択部品のワールドTRS行列を渡します。TRSは移動・回転・拡縮です。操作後の行列を分解し、JSONで使う術者基準の右・上・前へ戻します。

水平角をθ、ワールド移動を(dx,dy,dz)とすると、保存座標の増分は次です。

```text
右 = dx cosθ − dz sinθ
上 = dy
前 = dx sinθ + dz cosθ
```

発射イベントは角度を変えると位置オフセットの基準も回る設計です。そのまま角度だけを書き換えると、弾が術者の周りを回ってしまいます。`AttackPlacementMath::RotateEvent()`でサイズ依存のオフセットも含めて逆変換し、配置位置を保ちながら向きを変更します。初期のワールド位置は本編と同じ`ResolveAttackSequenceEmission()`で計算します。

trackのキー追加は`AttackPlacementMath::PutKey()`です。0.0001秒未満の近接キーは更新し、それ以外は追加して整列します。上限128個を超えた場合は通知します。

### GPU配置用の隔離

`GPUParticleManager`には配置用のGPUParticleSystem群を用意します。本編の放出先と分け、配置を更新したときだけリセットして素材を放出します。通常の時間更新には混ぜず、表示を停止して位置を編集できるようにします。離れると配置用表示を解除します。GPUリソースは再利用用に保持します。

描画は既存のCompute ShaderとIndirect Drawを使います。CPUで放出要求を作り、DrawでGPUバッファの初期化・放出・生存粒子リスト構築を行います。指定年齢での表示は既存の近似シークです。固定刻みの全フレーム、衝突履歴、乱数を完全再現するシミュレーションではありません。配置用システムは素材名でも分離し、主素材と補助素材の設定や放出年齢が混ざることを避けています。本編の移動中に繰り返し放出する軌跡の見た目は、全体の動作確認で調整してください。

## 7. 検証と残る範囲

- Development x64のソリューションビルド成功。Debugの全体ビルドは今回未実施ですが、ImGui側の追加はUSE_IMGUIに従います。
- AttackSequenceTests成功。既存攻撃の互換性、保存・再読込に加え、サイズ依存オフセットを持つ弾の回転位置維持、傾いた基準でのワールド移動、途中キーの追加・再編集、保存後の座標一致を確認しました。
- 実画面のギズモ操作・GPUの視認性は未確認です。Windows操作ツールが初期化で終了し、操作できませんでした。ビルド成功を描画・操作確認済みとは扱いません。

残る範囲は、全素材の画像カタログ、中央画面のObjectを直接クリックする選択、任意の親子構造、術者モデルの差し替え、全既存攻撃の共通ランタイム移行などです。今回の完成条件は、移行済み攻撃の部品を左から選び、配置用表示とギズモを通して保存データを編集するところです。
