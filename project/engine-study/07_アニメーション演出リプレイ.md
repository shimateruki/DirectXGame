# アニメーション、演出、リプレイ

詳細解説：[骨の補間と Animator](07A_骨の補間とAnimatorの状態遷移.md)。

[目次](00_目次と読み方.md)へ。共通して時間を扱うが、アニメーションは**姿勢や値の変化**、Cinematic は**演出の進行**、Replay は**起きた状態の記録**を扱う。

## アニメーションの基本

アニメーションは「時刻 → 姿勢・プロパティ」の対応を作る。キー間の値を滑らかにつなぐのが補間。クリップは一定区間のデータで、Animator Controller は現在の状態に応じてどのクリップを再生するかを管理する。[`BodyAnimationClip`](../engine/animation/BodyAnimationClip.cpp) と [`AnimatorController`](../engine/animation/AnimatorController.cpp) を並べて読むと、データと再生状態の責務を区別できる。

[`AnimationWorkbench`](../engine/utility/SystemDebug/editor/windows/AnimationWorkbench.cpp) は編集用の姿勢を組み立てる。時間軸の UI とその操作は [`AnimationWorkbench.Timeline.cpp`](../engine/utility/SystemDebug/editor/windows/AnimationWorkbench.Timeline.cpp)。プレビュー時に基本姿勢へ追加の姿勢・編集値を重ねる経路を読むと、なぜ見た目の確認と実ゲームの Animator 遷移が同じではないか分かる。キーを置いた場合は、補間値だけでなく保存先クリップへ反映されたかを確認する。

[`AnimatorControllerEditor`](../engine/utility/SystemDebug/editor/windows/AnimatorControllerEditor.cpp) は状態と遷移など Controller 側を編集する。クリップ内の動きを直すことと「いつその動きへ切り替えるか」を直すことは違う。動きが正しいのにゲーム中で再生されない場合は、Controller の状態・条件・ゲーム側の更新を確認する。

## タイムラインと再シミュレーション

タイムラインの横軸は秒に対応するが、エディターによって時間移動の実装が異なる。Animation Workbench は時間から補間姿勢を評価し、CPU 粒子は初期状態から再更新する。GPU 粒子は CPU 側の時刻を進めてから Draw で年齢を使った近似復元を行う。GPU の履歴依存の衝突まで再計算する機能ではない。**同じ形のシークバーでも内部の計算と再現精度が違う**。

## Cinematic と GhostDirector

[`CinematicPlayer`](../game/system/CinematicPlayer.cpp) はゲーム内演出の進行側。[`GhostDirector`](../game/system/GhostDirector.cpp) とその Studio 側 [`GhostDirector.Studio.cpp`](../game/system/GhostDirector.Studio.cpp) は演出データや編集用操作を持つ。演出の再生経路を理解する際は、開始条件、各フレームの更新、カメラ・Object・VFX・音声へ出す命令、終了時の元の状態への復帰を順に読む。プレイヤー操作を抑制する演出なら、開始時だけでなく途中中断時にも入力が復帰するかが重要。

## Replay Debugger は何を記録するか

[`GhostRecorder`](../engine/utility/SystemDebug/editor/misc/GhostRecorder.cpp) は指定 Object の位置・回転・拡縮と Event ID をサンプルとして記録し、`Resources/json/animation/` に保存して軌跡として再生する。60 サンプルを 1 秒とする記録と、指定秒への補間評価を持つ。Waypoint から Spline と Easing で軌跡を生成する編集もできる。これは Object 一つの演出軌跡を作る機能で、次の Replay Debugger が扱うゲーム状態の記録とは範囲が違う。

[`GameplayEventTrace`](../engine/utility/SystemDebug/GameplayEventTrace.cpp) は Animation Event から VFX・音声・カメラへ渡る処理を `Requested / Started / Fired / Completed / Cancelled / Warning / Failed` の段階で記録する。イベントが画面に出ないとき、要求自体が無いのか、発火後のアセット参照で止まったのかを切り分ける。これは時間軸の**診断ログ**で、演出データの保存先ではない。

[`ReplayDebugger`](../engine/utility/SystemDebug/editor/windows/replay/ReplayDebugger.cpp) はゲーム更新の前後へ接続される。[`GameEditorController`](../engine/core/editor/GameEditorController.cpp) 側の `UpdateBeforeSimulation` と `CaptureAfterSimulation` の呼び出し位置を見ると、再生入力や記録状態がゲーム更新のどちら側にあるかを追える。UI、保存、回帰チェックはそれぞれ [`Ui`](../engine/utility/SystemDebug/editor/windows/replay/ReplayDebugger.Ui.cpp)、[`Archive`](../engine/utility/SystemDebug/editor/windows/replay/ReplayDebugger.Archive.cpp)、[`Regression`](../engine/utility/SystemDebug/editor/windows/replay/ReplayDebugger.Regression.cpp) に分かれる。

Replay は編集操作の Undo ではない。記録したゲーム状態を再生・比較して不具合の再現を助ける。ゲームロジックの全てを逆算して過去へ戻す「一般的な時間逆行」でもない。記録対象外の外部ファイルや非決定的処理まで一致するかは個別に確認する。

## 読むときの確認項目

| 目的 | 見るべき点 |
| --- | --- |
| 動きの形を直す | クリップ、キー、補間、姿勢の合成順 |
| 再生の切替を直す | Controller の状態、遷移条件、ゲーム側から渡すパラメータ |
| 演出の順番を直す | Cinematic / GhostDirector のイベントと終了処理 |
| バグを再現する | Replay の記録開始位置、記録対象、実ゲーム更新との前後関係 |

プレビューが正しくても本番シーンで同じ結果になるかは、状態遷移、当たり判定、入力、カメラが同時に動く Play で確かめる。
