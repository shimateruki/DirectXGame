# 火球の全工程と、保存から本番まで

## 今回の「3・4」で変えた範囲

3は「火球一つの予備動作・発射・飛行・命中・終了をデータで再現する」、4は「保存・再読込・本番の命中まで検証する」です。

対象は炎スライムの **中距離火球** です。近距離ブレス、プリズムの各専用攻撃、ボス演出まで移行したという意味ではありません。

従来の共通化では、弾を生成する瞬間だけがJSONの命令でした。溜め、照準、予告線、色、反動は炎スライムのC++に残っていました。今回の火球では `sequence.actorControl.enabled = true` によって、そちらの専用分岐を通さず `EnemyAttackAction` が術者を制御します。

## 操作する場所

1. 敵攻撃エディターで「炎スライム」「中距離火球」を開きます。
2. 左の「攻撃全体の設定」から「共通実行シーケンス」→「術者制御」を開きます。
3. 予告終了、照準固定、警告時刻、予告の幅と色、本体色を設定します。
4. 左の弾Objectを選び、発生時刻・位置・速度・見た目・当たり判定・軌跡・着弾を調整します。
5. 左の「術者：溜めと発射後の反動」が姿勢のアニメーショントラックです。素材 `enemy_fireball_action` はAnimation Workbenchで編集できるJSONです。
6. 「保存せず動作確認」で攻撃全体を再生します。部品だけの配置表示はAIやダメージを動かしません。
7. 保存してから再読込し、変更が残ることを確認します。本番の既存Actorはプロファイルのコピーを持つので、シーンを開き直して新しいActorで確認します。

移行済み火球の下側にある旧「予備動作・攻撃継続・硬直」は無効表示です。現在の実行時間と無関係な欄を変更して混乱しないためです。「再使用間隔」は引き続き有効です。

下段の制作タイムラインでも照準固定と予備動作終了を変更できます。発射イベントの時刻とは独立しています。発射を遅らせた場合は予告や姿勢の区間も意図に合わせて調整してください。

## 火球一回の時間の流れ

| 攻撃開始から | 処理 | データ |
|---|---|---|
| 0秒 | 水平移動停止、照準追従、予告線、色変更、溜め姿勢 | `actorControl`、`body_animation` |
| 0.24秒 | 照準の方向・標的位置・距離を固定、警告 | `aimLockTime`、`cueTime` |
| 0.42秒 | 火球と発射粒子を生成、予告終了、本体色復帰 | `events[].time`、`telegraphEnd` |
| 0.42〜0.80秒 | 発射反動と後隙 | 姿勢クリップ、`sequence.duration` |
| 0.80秒 | 術者の攻撃終了、共通制御・姿勢の解除 | シーケンス終了 |
| その後1.45秒 | 次の攻撃まで待つ | `cooldown` |

**術者の攻撃終了と、飛んでいる弾の消滅は別です。** 弾はBulletManagerが所有し、命中または寿命2.65秒で消えます。シーケンスが終わった瞬間に飛行中の弾を消してはいけません。

今回、再使用待ちは後隙終了から数えます。以前は発射付近からクールダウンを数えていたため、連射周期は同一ではありません。従来の発射間隔へ近づけたい場合は再使用間隔を後隙の分だけ短くして調整します。

## 使っている技術と、分担

### 1. データ駆動とコンポジション

攻撃名をC++の `if` で列挙せず、予告・本体姿勢・弾・GPU放出などの部品を組み合わせます。JSONはプログラムそのものではありません。C++が用意した操作の種類と、そのパラメーター・実行時刻を記録するデータです。

`EnemyFireSlime` のAIは距離などから候補を選択します。選んだ攻撃に術者制御が設定されていれば、`EnemyAttackAction`へ渡します。新しい攻撃IDでも同じ経路に入るため、同じ部品で表現できる別の火球攻撃なら敵クラスへ新しい分岐を追加する必要はありません。

### 2. 実行中のスナップショット

`AttackSequence::Start` は定義をコピーします。再生中に編集や再読込で元のデータが変わっても、その攻撃の途中から別の設定へ入れ替わりません。次の開始から新しい定義を使います。

Editorの未保存プレビューも編集データのコピーを隔離Actorへ渡します。通常の本番Actorに未保存データを注入する経路ではありません。

### 3. 時刻によるイベント発火

`AttackSequenceClock` は開始からの経過秒で命令を実行します。1フレームでイベント時刻を通り過ぎても、到達した命令を時刻順に一度だけ実行します。

術者制御も同じ経過時間を読むため、敵固有の溜めタイマーとシーケンスタイマーがずれる構造を避けられます。AIが攻撃を選ぶまでの時間はこの0秒より前です。プレビュー全体の再生時刻と攻撃ローカル時刻を混同しないでください。

### 4. ロックオン位置のスナップショット

照準固定前は更新時点の標的位置を取得し、固定後は方向・標的位置・速度計算用距離を保持します。以前のように「予告線だけは固定されているが、発射時には最新のプレイヤー位置を狙い直す」という食い違いを避けます。

標的を失っても攻撃時計は進めます。対象必須条件の命令はその時点の `hasTarget` で判定し、終了時に予告・着色・姿勢を解除します。固定時刻の標的位置はフレーム単位のサンプリングであり、フレーム間の移動を遡って再構成する機能ではありません。

### 5. キーフレーム補間と描画用変換

`enemy_fireball_action.json` に溜め・圧縮・発射反動・復帰のキーを保存します。`BodyAnimationClip` が時刻間の姿勢を補間し、`AttackSequence` が描画用の行列としてRendererへ渡します。

これはObject一体の位置・回転・拡縮を変えるクリップです。Blenderのボーンアニメーションを何でもそのまま扱えるようにした変更ではありません。見た目の潰れに合わせて物理Colliderまで伸縮させる必要はないため、描画姿勢と物理形状を分離しています。

### 6. 弾の生成、飛行、実際の被弾

`AttackSequence::Execute` → `BulletManager::Fire` → `Bullet::Update` の順で生成・移動します。弾の衝突対象はカテゴリ名から取得します。敵の弾なら `enemy_attack` で、プレイヤーや地面が対象です。

本番は `CollisionManager` → `Player::OnCollision` → `DamageEvent` → `GameRule` という経路でHPを減らします。プレビューだけHPを手動減算して、本番で動いたことにする検証はしません。

外観の大きさと衝突半径は独立しています。判定OFFでは対象にも地形にも衝突せず寿命まで飛びます。命中演出は衝突時、軌跡は飛行中の間隔放出です。

### 7. 保存の置換とキャッシュの無効化

プロファイルは一時ファイルへ全体を書き、書込み・closeの成功後に `MoveFileExW` で置換します。不正な値は書込み前に拒否します。日本語パスはUTF-8からWindowsのパス型に変換して読み書きします。

保存成功後はプロファイルキャッシュを無効化します。ただし、すでに生成された敵が保持しているコピーまで勝手に変更しません。共有アセットは別ファイルなので、プロファイルと共有アセットの複数ファイルを一括でロールバックするトランザクションではありません。

## 検証

`tests/AttackSequenceTests.cpp` はJSON往復保存、時計、条件、部品編集、配置、術者設定、不正な保存による既存ファイル破損の防止を検証します。

実行テストは次のコマンドです。通常起動ではテスト用処理は動きません。

```powershell
./tests/RunSceneTransitionRuntimeProbe.ps1 -AttackLifecycle -Debugger
```

この検証は火球から別IDの攻撃を作成して保存し、開き直し、実GAMEPLAYへ通常のFactoryで敵を生成します。優先度によるAI選択、弾生成、実PlayerのHP減少、判定OFFでの無傷、弾の寿命終了を確認します。障害物との偶然の接触を避けるため、テスト中の敵とプレイヤーは上空へ配置し重力を止めます。ステージの全地点での遮蔽・足場の検証とは区別してください。

テスト起動スクリプトは終了時に火球JSONとユーザー設定を元のバイト列へ復元します。既存ゲームが起動中の場合は開始しません。

### 今回の実測結果（2026-10-08）

- Development x64ビルド成功。
- `AttackSequenceTests` 全項目成功。術者制御の値も保存・再読込で一致。
- CDB下の実GAMEPLAY実行で `runtime_authored_attack` をJSONへ保存・再読込し、通常AIが選択。
- 判定ON：実PlayerのHP **20 → 18**、弾によるDamageEvent **1回**。
- 判定OFFへ変更して保存・再生成：HP **20 → 20**、DamageEvent **0回**。
- 両方で発射と攻撃終了を観測。判定OFFの弾が寿命後に残っていないことも確認。
- 正常終了 `ExitCode=0`。CDBのアクセス違反・未処理例外検出なし。終了後にテスト用攻撃が元JSONへ残っていないことを確認。
- ログ：`%TEMP%/cg2-fireball-lifecycle-runtime.log`、同名に `.debugger.txt` を付けたCDBログ。

これは自動実行した機能確認です。ImGuiの全項目をマウスで操作した確認や、攻撃の見栄えの目視評価は含みません。

## 追補：通常再生とグリッドが止まっていた問題

攻撃編集用のギズモと通常Sceneの操作が競合しないよう、`GameEditorController.Viewport.cpp` で攻撃編集時の `DebugEditor::Update()` 呼出しを省いていました。しかし、この関数には入力処理だけでなく `EnemyAttackPreviewWindow::Update()` と `EffectPreviewStage::Update()` も含まれていました。

その結果、通常再生の時計が進まず、隔離空間の床とグリッドの生成・更新も止まりました。コマ送りはボタンから `SeekPreview()` を直接呼ぶため、この更新漏れがあっても動いていました。

修正後は攻撃編集中も `DebugEditor::Update()` を呼びます。プレビュー更新とScene切替時の参照整理を終えてから、通常Sceneの選択・配置・ギズモの入力処理だけを抑制します。

回帰確認は次のコマンドです。`Update()` をテストから直接呼ばず、Game Viewの通常経路で時間が進むか確認します。

```powershell
./tests/RunSceneTransitionRuntimeProbe.ps1 -AttackEditor -Debugger
```

再生、停止、1フレーム送り、再開、配置表示から再生への切替を検査し、表示中のグリッドObject数も確認します。このテストは攻撃JSONを書き換えません。

2026-10-08の実行結果：攻撃エディターの選択を維持した状態で、通常再生は0→0.5秒、停止後の1フレーム送りは0.516667秒、再開後は1.01667秒まで進みました。配置表示から再生へ戻った場合も0→0.5秒まで進み、各確認時点で表示状態のグリッドは42本でした。停止・コマ送り後の待機中には時間が進まないことも検証しています。CDB下で全項目PASS、正常終了コード0です。ログは `%TEMP%/cg2-attack-editor-verified.log` にあります。画面操作ツールの接続失敗により、マウスでの操作とスクリーンショットの目視確認は未実施です。

## 残る範囲

- 近距離ブレス・プリズム固有演出など、他の攻撃の全工程移行。
- 本体アニメーションに使う汎用的なボーン／リグの編集・取込み。
- 攻撃エディターのすべての設定をまとめたUndo、共有アセット複数件の保存管理。
- 弾の追尾・反射など、まだ弾部品に存在しない挙動。
- 火の外観とダメージ属性の完全な分離。現行の弾は炎スタイルから火属性を選ぶ仕様が残ります。
- ImGuizmoを実際のマウス操作で扱ったときの使い勝手の確認。

一つの火球を共通データで通す段階であり、あらゆる敵や攻撃を自由に作れるエディターが完成したという位置付けではありません。
