# 3. シェーダーとマテリアル — 技術名と見た目の対応

詳細解説：[体積炎のレイマーチング](03A_体積炎のレイマーチング.md) / [水と局所霧の式](03B_水と局所霧の見た目を作る式.md)。

## 3-1. シェーダーとは

Vertex Shader は主に頂点を画面へ投影し、Pixel Shader はピクセルの色や透明度を計算します。Compute Shader は描画の形に限定されず、Buffer 上のデータを並列に更新します。このプロジェクトの HLSL は [`Resources/shader`](../../Resources/shader) にあります。C++ 側の PSO と Root Signature が選択・接続するため、HLSL ファイル単独では完成した効果になりません。

## 3-2. 標準的な 3D マテリアル

[`Object3d.PS.hlsl`](../../Resources/shader/object3d/Object3d.PS.hlsl) には Cook–Torrance 型の PBR 経路があります。`DistributionGGX` は微小面の法線分布、`GeometrySchlickGGX` は微小面による遮蔽、`FresnelSchlick` は見る角度による反射率変化を近似します。`roughness` はハイライトの広がり、`metallic` は金属としての反射特性を制御します。Normal Map は表面の細かな向きを変え、ORM Map は Occlusion/Roughness/Metallic の情報をまとめます。

これは「すべての材質が同じ PBR 式だけで描かれる」という意味ではありません。同ファイルには材質種別ごとの分岐や Stylized Terrain もあります。Material Type を変えた時は、実際にどの分岐を通るか確認してください。

## 3-3. Shadow Map と PCF

[`DirectXCommon::CreateShadowMap`](../../engine/graphics/core/DirectXCommon.cpp) が光視点の深度 Texture を用意し、[`Game::DrawSceneToRenderTexture`](../../engine/core/Game.cpp) の影パスで書き込みます。通常描画の Pixel Shader は光空間へ投影した深度と比較します。近傍 3×3 サンプルを平均しているため、境界は硬い一段の影より少し滑らかになります。これは Percentage-Closer Filtering（PCF）の考え方です。

## 3-4. 炎の「体積レイマーチング」はどこで使うか

**実際に体積サンプリングしているのは [`FireVolume.hlsli`](../../Resources/shader/materials/FireVolume.hlsli) の `RenderFireVolume` です。** [`Fire.PS.hlsl`](../../Resources/shader/materials/Fire.PS.hlsl) から条件に応じて呼び出されます。

1. ピクセルの画面座標と深度から、カメラの近点・遠点をワールド座標へ復元する。
2. レイをエフェクトのローカル座標へ変換し、箱との交差区間を計算する。
3. シーンの深度を読んで、背後の不透明物体より先でサンプリングを打ち切る。
4. 区間を 24 または 32 ステップに分け、各位置の密度と熱量を計算する。
5. 密度から不透明度を求め、手前から色を積算し、透過率が十分小さくなれば早期終了する。

この方式だと平面の炎 Texture を正面へ貼るだけの場合より、内部の濃淡・奥行き・重なりを表現できます。一方でステップ数にほぼ比例して Pixel Shader の仕事が増えます。`FireVolume.hlsli` の固定ステップサンプリングはボリュームレイマーチングであり、SDF の表面まで距離分だけ飛ぶ Sphere Tracing とは別です。

## 3-5. 雲・霧・水は同じ方式か

いいえ。[`Cloud.PS.hlsl`](../../Resources/shader/materials/Cloud.PS.hlsl) は 2D fBm ノイズを重ねた雲形状、深度による遮蔽、画面の Grab Texture をずらす歪みを組み合わせます。炎のように各ピクセルで 24/32 点の密度を積算する経路ではありません。

[`LocalFog.PS.hlsl`](../../Resources/shader/materials/LocalFog.PS.hlsl) は深度から背景位置を復元し、霧 Box と視線が重なる厚みを求めます。3D ノイズや光方向で濃さと色を変えますが、現行コードの中心は交差長と中点サンプルに基づく計算です。「炎と同じ多段レイマーチング」とまとめない方が正確です。

[`Water.PS.hlsl`](../../Resources/shader/materials/Water.PS.hlsl) は複数スケールの波面、傾き、空の反射色、深度から復元する水中側の情報などを組み合わせます。上から見た波紋と、斜めから見た反射は同じパラメータだけで決まりません。

## 3-6. ポストエフェクト

[`PostEffect`](../../engine/graphics/postprocess/PostEffect.cpp) はシーンを Render Texture に描いた後の画像処理です。[`PostEffect.PS.hlsl`](../../Resources/shader/postprocess/PostEffect.PS.hlsl) に Bloom、Tone Mapping、Vignette、Chromatic Aberration、Radial Blur、Dissolve、Grayscale などの計算があります。Bloom は明るい領域の抽出・ぼかし・合成で光の広がりを作ります。Tone Mapping は HDR の明るさを表示可能な範囲へ圧縮します。`PostEffectEditor` の UI 値がこのパラメータへ渡されます。

## 3-7. 見た目を調べる順番

対象 Object の Material Type → C++ 側で選ぶ PSO → Vertex/Pixel Shader → `register(...)` に接続される Texture/Buffer → Blend と Depth の状態 → PostEffect の順に追います。見た目が違う原因が Shader の式ではなく、古い Material Type、違う Texture、深度の遮蔽、描画順の場合もあります。
