# ポリモーフィズム修正記録

[目次](00_目次と読み方.md) / [元の調査](21_ポリモーフィズム調査.md)

## 対象と判断

2026-10-09 の現行コードを調べ、[元の調査](21_ポリモーフィズム調査.md)で挙げた複製、シーンイベント、敵生成後の接続、攻撃プレビューの四系統を修正した。型の列挙が保存データを C++ 型へ変換する入口にある場合は残し、生成後の振る舞いを派生型へ移せる箇所を変更した。

## 修正内容

| 対象 | 修正したロジック | 目的 |
| --- | --- | --- |
| [`DebugEditor.Commands.cpp`](../engine/utility/SystemDebug/editor/core/DebugEditor.Commands.cpp) | 単体・複数の複製、Undo/Redo の再生成を、敵・ギミック・アイテムの Factory と保存状態から行う。取得した実行型が複製元と一致するかを確認する。 | `Object3d*` から `Clone()` を呼んだときに派生型が `Character` や `BaseGimmick` へ変わる問題と、複数選択・Undo/Redo で常に素の `Object3d` になっていた問題を防ぐ。 |
| `Object3d`・`Character`・`BaseGimmick` の `Clone()` | 自分より派生した型が `Clone()` を上書きしていなければ `nullptr` を返す。呼び出し側の王冠ムービーでも失敗を確認する。 | Editor 以外の呼び出しでも、派生型を失った複製を静かに作らない。 |
| Editor の未対応型 | Factory で同じ実行型を復元できない場合は複製を中止し、ログへ理由を出す。削除前にも復元可否を調べ、Undo で別型になる削除を止める。 | 見た目だけ同じ別クラスの生成や、Undo 後の振る舞いの消失を防ぐ。 |
| [`LevelLoader`](../game/system/LevelLoader.cpp) と敵 | 共通の `BaseEnemy::BindSceneSpawnContext()` でターゲットを接続し、`EnemyBomber` と `EnemyPrismSlime` がスポーン用コールバックを上書きして接続する。召喚された敵にも同じ入口を使う。 | 敵生成後の `dynamic_cast` の列挙を減らし、敵自身が必要なシーン参照を定義する。 |
| [`GameRule`](../game/system/GameRule.cpp) とシーン | Goal・StarCoin の接触処理を [`IStageProgressScene`](../game/system/IStageProgressScene.h) 経由で呼ぶ。`GamePlayScene` と `PreviewScene` が演出・進行状態・従来のログをそれぞれ実装する。 | `GameRule` が二つの具象シーンを列挙して分岐する箇所を、対応シーンだけの能力へ移す。 |
| 敵の攻撃プレビュー | `BaseEnemy` にあった空の既定関数を除き、[`ISequencePreviewEnemy`](../game/actor/enemy/combat/ISequencePreviewEnemy.h) を `EnemyFireSlime` と `EnemyPrismSlime` が実装する。Editor と既存の実行検証用コードもこの能力を確認して使う。 | すべての敵が対応しているように見える API をなくす。 |

Editor の一時的な状態記録には `_editorRuntimeType` を追加した。これは実行中の Undo/Redo が型を確認するための値であり、Scene JSON の保存形式には追加していない。Factory が代替の基底オブジェクトを返した場合も型比較で拒否する。敵を復元した際のターゲットとスポーン先は、その敵だけに接続し直す。

## 修正後の扱い

- `EnemyBomber`、`EnemyBomb`、`GimmickTrampoline` など、Factory が元と同じ型を作れるものは、Editor の保存状態から複製・復元できる。
- `Player`、`PlayerClone`、`Bullet`、`EnemySpawner` など、同じ型を再生成する Editor 用 Factory がないものは複製を拒否する。削除も Undo で同じ型に戻せないため拒否する。これらを編集対象にする場合は、初期化とシーンへの参照接続を含む専用の復元経路が必要。
- `BaseScene` のリソース・Player・GameRule を返す既定の `nullptr` API は、LevelLoader や Editor からの既存の参照契約として今回は残した。単純な削除や純粋仮想化では、対応しないシーンまで実装を強制する。
- 橋ムービーは `GamePlayScene` 固有のイベントとして具象型への一回の分岐を残した。Goal・StarCoin のように複数シーンで共有する処理とは分けている。
- ObjectManager の更新順と各 Factory の文字列分岐は、順序制御と JSON からの生成という明確な役割があるため変更していない。
