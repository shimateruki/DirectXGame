# 共通攻撃シーケンスの制作と移行

[目次](../00_目次と読み方.md)へ。2026-10-07の改良で、炎スライムの火球と炎コピーのE攻撃を共通シーケンスへ接続した。新しい火球の派生は、攻撃の複製とJSON設定だけで増やせる。全敵・全能力の移行が完了したという意味ではない。

同日の追加で、プリズムスライムの炎の扇状連射も接続した。[プリズム炎連射と魔法陣の技術解説](14C_プリズム炎連射と魔法陣の技術解説.md)に、時間差連射のJSON、水平角度・基準サイズに比例した位置、炎の外観設定と、魔法陣の描画技術を詳しくまとめている。プリズムは詠唱完了を命令の時刻0とするため、本章の炎スライム・炎コピーとは開始点が異なる。

## 今回できるようになったこと

敵の「中距離火球」とプレイヤーの「プレイヤー炎火球」は、同じ[`AttackSequence`](../../game/actor/combat/AttackSequence.cpp)で弾生成とGPUパーティクル命令を実行する。攻撃ID、発射時刻、発射数、拡散角、条件、威力、速度、寿命、再使用時間をデータで持つ。敵AIは射程と優先度から候補を選び、プレイヤーはE入力から候補を選ぶ。エディターも実際の敵・Playerを生成して同じ処理へ入力を渡す。

新規攻撃ごとにエディターへ分岐を足す必要はない。設定イベントの印はJSONのイベント配列から描き、実行状態は役者が共通ランタイムから返す文字列を観測する。既存の専用攻撃は従来の経路で動作する。

## 操作例：敵の三方向火球を作る

1. Hierarchyの「敵攻撃プレビュー」を開き、炎スライムの「中距離火球」を選ぶ。
2. 「共通攻撃を追加・選択攻撃から複製」を押す。重複しないIDが発行される。
3. 表示名を変更する。「共通実行シーケンス」で実行先を「敵AI」にする。
4. 弾発射イベントの同時発射数を3、拡散角度を30度などにする。
5. 射程、威力、弾の半径、最低・最高速度、寿命を調整する。
6. 「保存してプレビューへ反映」を押す。JSON保存、キャッシュ無効化、役者の再生成が行われる。
7. Play中は同じ射程にある攻撃のうち優先度が高いものを選ぶ。複製時は元より優先度を1上げる。同値ならファイル内の順序が優先される。

「標的が射程内」をイベント条件にすると、発射時点で射程外ならその命令を飛ばせる。「条件不成立なら後続命令も中止」を有効にすると、後続の命令も実行せず終了する。すでに飛んだ弾の削除や、接続先の硬直を即座に終える命令ではない。任意のノードへのジャンプや、条件成立まで待機する命令は今回の対象外。

## プレイヤー側で使う

「プレイヤー能力プレビュー」で炎を選び、「確認する動作」をE技にする。攻撃プロファイルの「編集・観測する攻撃」でプレイヤー用の定義を選択できる。複製した定義の実行先は「プレイヤーE入力」にする。Playでは優先度が高いプレイヤー用定義を使い、プレビューでは選択中の定義IDを優先する。

保存済みコピーの適用は、以前の`CreateDefault`直呼びから`LoadCachedForEnemy`へ変更した。これにより、記憶台などからのコピーとプレビューもJSONを読む。通常の敵からのコピーは、引き続き敵が保持するプロファイルを能力セッションへ渡す。セッションは設定のコピーを保持するため、すでにPlay中の敵やコピー能力へ編集内容を一斉に書き換える機構ではない。保存後は再生成・再取得した対象で確認する。

炎コピーは前方へ発射する。現在この接続では標的ポインタを共通ランタイムへ渡していないので、「標的が射程内」は成立しない。プレイヤー用には常時・接地中・空中の条件を使用する。既存のブレス、ダッシュ、他属性の複雑な能力は今回のシーケンスへ移していない。

## データと実行の分担

| 実装 | 担当 |
| --- | --- |

| [`AttackSequence.cpp`](../../game/actor/combat/AttackSequence.cpp) | 共通の条件評価、弾生成、GPU粒子の発火、観測ラベル |
| [`EnemyAttackProfile.cpp`](../../game/actor/enemy/combat/EnemyAttackProfile.cpp) | JSON読込・保存・旧データの既定値補完 |
| [`EnemyFireSlime.cpp`](../../game/actor/enemy/elemental/EnemyFireSlime.cpp) | 敵AIの選択、予兆、役者の位置・標的・接地情報の供給 |
| [`FireSlimeCopyAbility.cpp`](../../game/actor/player/copy/FireSlimeCopyAbility.cpp) | E入力の受付、アニメーション、プレイヤー情報の供給 |
| [`EnemyAttackPreviewWindow.Ui.cpp`](../../engine/utility/SystemDebug/editor/windows/EnemyAttackPreviewWindow.Ui.cpp) | 複製、イベント・条件・弾パラメーターの編集、保存 |
| [`EnemyAttackPreviewWindow.Timeline.cpp`](../../engine/utility/SystemDebug/editor/windows/EnemyAttackPreviewWindow.Timeline.cpp) | 設定イベントの印と実行状態の観測 |

敵・プレイヤーの攻撃データは[`fire_slime.json`](../../Resources/json/enemy_attack/fire_slime.json)にある。敵用は`fireball`、プレイヤー用は`player_fireball`。JSON上の`sequence`が共通命令を保持する。

```json
{
  "enabled": true,
  "binding": "enemy",
  "priority": 1,
  "duration": 0.42,
  "projectileStyle": "fire",
  "visualScale": 1.2,
  "events": [
    {
      "time": 0.42,
      "operation": "projectile",
      "condition": "target_in_range",
      "stopOnFalse": true,
      "offset": [0, 1.05, 0.65],
      "aimAtTarget": true,
      "distanceSpeedScale": 1.65,
      "count": 3,
      "spreadDegrees": 30
    }
  ]
}
```

これは`sequence`部分の例。威力・半径・速度・寿命は同じ攻撃の`combat`、`targeting`、`movement`にある値を使う。位置の配列は「右・上・前」、時刻は秒、拡散角は度。距離倍率が0なら最高速度で発射し、正なら標的距離に掛けた速度を最低～最高速度へ収める。陣営に応じた衝突カテゴリは共通C++処理が設定する。

`gpu_vfx`命令は`preset`の名前で既存GPUパーティクルを発火する。弾の外観部品は今回「炎」「通常」の2種類。炎のシェーダーや軌跡・着弾の構成自体は共通C++部品に残る。外観の組み合わせを全面的にデータ化した段階ではない。

## 時計と観測

開始時に設定をコピーし、命令を時刻順に安定ソートする。同時刻の命令はデータ内の順を保つ。時刻0の命令も開始フレームに実行する。更新で複数の時刻をまたいでも、その区間の命令を各1回ずつ処理する。イベントの上限128件、同時発射数32、再生時間30秒の検証を読込・保存・開始で共有し、未対応の命令や範囲外時刻は拒否する。

条件はイベント時点の役者情報で評価する。失敗時のスキップと終了は時計が管理する。能力解除や炎ダッシュ開始などではシーケンスを中断し、未実行の命令が後から出ないようにする。発射済み弾は従来どおりBulletManagerが所有し、攻撃中断と同時に消す仕様ではない。

タイムラインの「共通命令」は攻撃開始を0秒とした設定表示。プレビュー全体の0秒や敵AIの攻撃開始時刻とは一致しない場合がある。実測フェーズには攻撃名、実行中／終了、発火数、条件不成立数が出る。シークは従来どおり役者を再生成して固定刻みで再実行する。

## 移行の範囲と次の接続点

今回の共通命令で新しい攻撃を増やせる役者は、炎スライムの敵AIと炎コピーE入力。別の敵への接続、近接判定、移動、着地までの待機、コンボ分岐、HP条件、任意の状態遷移はまだ専用C++処理に残っている。共通命令を一度実装すれば、その命令を組み合わせる派生攻撃には新しいC++処理を要しない、という境界を今回の火球で作った。

今後は、この実行経路を維持したまま必要な命令・条件と役者側の接続を増やす。観測側には各攻撃のIDや具体的な発射パターンを追加しない。
