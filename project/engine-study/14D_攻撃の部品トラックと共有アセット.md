# 攻撃の部品トラックと共有アセット

## 1. 今回変えた制作単位

攻撃を「C++で完成した処理の数値を調整するもの」から、「共通の命令と部品をデータで組み合わせるもの」へ移すための変更です。

今回追加した部品は **表示物（mesh_vfx）** と **球形の攻撃判定（hitbox）** です。
従来の弾発射とGPU粒子の単発イベントも併用できます。
表示物を0～1秒、判定を0.3～0.5秒に設定すれば、予告・命中・消滅を別々のC++関数へ書かなくても、その時間関係を作れます。

ただし、全攻撃の移行完了ではありません。
現時点の接続先は炎スライムの共通攻撃、プレイヤーの炎コピーE入力、プリズムスライムの共通炎攻撃経路です。
雷・風・特殊ボス攻撃の専用処理、キャラクター本体の手続きアニメーション、AIの大きな行動選択は引き続き既存コードが担当します。

## 3. エディターの操作

### 制作と観測の入口（2026-10-07の追補）

以前は共通ランタイムが有効な攻撃だけで専用Hierarchyを表示していました。
そのため、炎スライムの「近距離炎ブレス」を選んでいると通常のシーン一覧と観測グラフが残り、制作機能を見つけにくい状態でした。
現在は炎スライム／プリズムの攻撃プレビューで、未移行の攻撃を選んでも左側に制作への入口を表示します。

- `[観測]`: 動作はまだC++側。既存パラメータの調整・確認を行う対象。
- `[制作]`: 共通ランタイムの命令・部品を組み合わせて編集できる対象。
- **空の攻撃を新規作成**: 独立した攻撃IDを作る。部品か単発命令を追加するまで保存できない。
- **表示＋判定の例から作成**: サンプルを複製し、表示物と判定を一組持つ新規攻撃を作る。
- **二段攻撃の例から作成**: 二組の部品を持つ新規攻撃を作る。

例から作る場合、近接判定へ標的が届く距離設定も一緒に用意します。
元のブレスや見本JSONは上書きしません。部品を選ぶと右のInspectorがその部品の編集画面になります。
不要な新規攻撃は「この作成した攻撃を削除」で取り除けます。削除のファイルへの反映も保存時です。
「保存して再生」でプロファイルを保存してプレビューを開始します。保存した攻撃は本編の攻撃候補にもなります。
攻撃全体の威力・射程などに戻るときは、左の「攻撃全体の設定」を選びます。

この追補ではプレビュー標的の接続も修正しました。
以前のプレイヤー標的は衝突属性が0だったため、共通判定トラックのPhysics Queryから除外されていました。
現在はplayer属性を保持し、衝突マスクだけを0にします。通常の接触応答は止めながら、対象カテゴリによる問い合わせを可能にします。
実際の画面操作・HP減少は、このコード接続とビルドの確認とは別の実機確認事項です。

1. Enemy Attack PreviewでFireSlimeの共通攻撃、またはPlayer Ability Previewで炎コピーのE攻撃を選びます。
2. 「共通攻撃を追加・選択攻撃から複製」で別の攻撃IDを作れます。複製時は共有参照を解除し、元アセットの上書きを防ぎます。
3. 左の「攻撃の構成」から制作対象を選ぶか、新規作成します。
4. 「表示物を追加」「判定を追加」で部品を増やします。これはシーン内の実物を編集する一覧ではなく、攻撃データの一覧です。
5. 部品を選び、Inspectorの「選択した攻撃部品」で開始・終了、位置キー、補間、追従を設定します。
6. 表示物はMeshEffect Editorで保存済みのプリセットを選びます。判定は球半径とダメージ倍率を設定します。
7. 下段の「攻撃内容の時間軸」で棒の中央をドラッグすると移動、左右端をドラッグすると区間の伸縮です。伸縮時は内部キーの時間も比例して変更します。
8. 「保存して再生」でJSONを保存し、プレビューを開始・再生成します。再生中の攻撃へ編集値を直接差し込む方式ではありません。

「元に戻す」「やり直す」は、この攻撃制作UIで変更したシーケンスの履歴です。最大64件です。
別攻撃への選択変更・プロファイルの再読込では履歴を破棄します。
既存の射程・威力などプロファイル全体の編集履歴、保存済みファイルの復元までは扱いません。

### 時間軸の原点

新しい時間軸の0秒は **AttackSequence::Startが呼ばれた時刻** です。
既存の観測タイムラインはプレビュー開始からの時刻です。敵の接近や予備動作があるため、両者の0秒は一致しません。
プリズムスライムでは共通シーケンスは予備動作の後、Active開始時に起動します。

## 4. 二種類の時間処理

### 単発イベント

弾発射とGPU粒子放出は、時計が指定時刻を通過したときに一度だけ実行します。
イベントカーソルを先へ進めるため、一時停止の更新や通常の次フレームで同じ弾を再発射しません。
大きなdeltaTimeで複数イベントを通過しても、安定ソートした時間順で通知します。

### 区間トラック

表示物・判定には開始と終了があり、有効区間は `[begin, end)` です。
トラック内のキー時刻は、攻撃開始ではなく **そのトラックの開始からの秒数** です。
開始条件は最初に区間へ到達した更新で一度評価し、その攻撃中は結果を維持します。
接地条件が途中で変わって部品が毎フレーム生成・削除されることを避けています。

接地、空中、射程内、常時という条件を使用できます。
任意の式、命中後の別セクションへの遷移、入力待ち、ループグラフは今回の実装には含まれていません。

## 5. キーフレーム補間

時刻tに対して、前後のキーA・Bを探し、区間内の割合を求めます。

```text
u = clamp((t - A.time) / (B.time - A.time), 0, 1)
線形:       p = A + (B - A) * u
Smoothstep: p = A + (B - A) * (u * u * (3 - 2u))
保持:       Bの時刻まではA、Bの時刻になったらB
```

位置・回転・スケールをそれぞれ補間します。回転はEuler角の成分補間で、QuaternionのSlerpではありません。
360度をまたぐ最短回転を自動選択しないため、意図した回転方向になる数値をキーに設定します。
位置は術者の右・上・前、回転はラジアン、スケールは倍率です。

毎フレーム現在値へ移動量を足す方法ではなく、絶対時刻から値を求めます。
これを「絶対時刻評価」と呼びます。表示物自身の姿は再生刻みの違いによる積分誤差を蓄積しません。
ただしプレビュー全体は既存のAI・物理を先頭から固定刻みで再実行してシークするため、攻撃全体の任意時刻を直接復元できるという意味ではありません。

## 6. ローカル座標をワールド座標へ変える

術者の前方を水平面へ投影し、正規化したFを作ります。Fから右方向Rを作ります。

```text
F = normalize((forward.x, 0, forward.z))
R = (F.z, 0, -F.x)
world = actorPosition + R * local.x + (0, local.y, 0) + F * local.z
```

前方がゼロなら+Zへフォールバックします。
「術者に追従」を有効にすると更新時の座標・向き、無効なら攻撃開始時の座標・向きを使います。
これはキャラクターのボーンへのソケット追従ではありません。ボーン指定・部品間の親子階層は今後の接続項目です。

## 7. 表示物の時間・所有権

通常のMeshEffectManagerは自分のdeltaTimeでエフェクトを進めます。
攻撃トラックでも同時に時間を加えると、二重更新になったり、停止中に表示物だけ消えたりします。

そこで攻撃トラックは **スコープID** を受け取り、表示物の時間と寿命を攻撃側が管理します。

1. 開始時にStartTimelineEffectでプリセットから表示物を作る。
2. EvaluateTimelineEffectで指定秒の色・ディゾルブを評価する。
3. 位置・回転・スケールを攻撃トラックのキーで上書きする。
4. 通常のMeshEffectManager::Updateは、その表示物へ時間を加算しない。
5. 終了・Cancel・AttackSequenceの破棄時に、該当スコープだけを消す。

この所有権のまとまりによって、別の敵や別ツールのエフェクトを全消去せずに片付けられます。
VolumeModeによる交差面・厚みのための相対配置は保持します。
プリセット内の衝突設定は無効化し、攻撃判定は専用トラックだけで処理します。

表示には既存のEffectObject3dとEffect3dシェーダーを使用します。
今回追加したサンプルのwarning flashは、プリセットのテクスチャ・色・透明度を使う表示です。
攻撃トラックを使うこと自体がレイマーチングや新しいシェーダーを導入するわけではありません。

## 8. 当たり判定とダメージの流れ

判定トラックは、見えない球形の攻撃範囲です。表示物のスケールを変更しても判定半径は変わりません。
位置キーで移動させられます。前回と今回の評価位置の間をCollisionManager::OverlapCapsuleへ渡し、移動中の接触を近似します。
途中のキーを通過した場合は区切って問い合わせます。「保持」による瞬間移動では着地点のOverlapSphereだけを使います。
このエンジンのOverlapCapsuleは球を並べる近似で、厳密な連続衝突判定（CCD）ではありません。

命中候補には次の制限を適用します。

- 敵の攻撃ならplayerカテゴリ、プレイヤーの攻撃ならenemyカテゴリ。
- 攻撃者自身とその子孫を除外。
- 同じトラックでは同じReplay IDへ一回だけ通知。
- EditorInternalのプレビューActorと通常Actorを混ぜない。

命中するとDamageEventを発行し、威力は `プロファイルのdamage × トラックのdamageScale` です。
ノックバックと無敵時間は既存の攻撃定義から読みます。
HP、ガード、死亡等の最終処理は既存のイベント受信側が担当します。判定トラックが直接HPを書き換える方式ではありません。
今回の球トラックは物理ダメージです。弾側の状態異常設定とは別で、球トラックへの属性・状態異常選択は未接続です。

二段攻撃は二つの判定トラックで構成できます。ただし被弾無敵中なら二段目のDamageEventが受信側で無効になることがあります。
「イベントを二回通知した」ことと「HPが二回減った」ことは区別してください。

## 9. 共有アセットと割り当て

保存先は `Resources/json/attack_assets/名前.json` です。
攻撃内容の時間・イベント・トラックを保存し、プロファイルはsequence.assetPathから参照します。

```text
敵プロファイル ── binding=enemy ─────────┐
                                        ├─ 共通攻撃アセット
プレイヤー設定 ─ binding=player_special ─┘
```

bindingとpriorityは利用先側で維持します。攻撃内容を読み込んだ結果、プレイヤー用設定が敵AI用に変わることはありません。
威力・射程・クールダウンなどは既存のプロファイル側です。同じ攻撃内容を敵とプレイヤーで使い、威力を変えられます。
この分担は完全なAbility Systemではなく、現行プロファイルとの移行境界です。

共有アセットを更新すると、参照するプロファイルの次回読込で新しい内容が使われます。
実行中のAttackSequenceは値コピーを保持するため、保存途中で攻撃内容が変化しません。
すでに生成済みの本編Actor全体を即時ホットリロードする処理は追加していません。

共有アセットの保存は、一時ファイルへの書き込みが成功した後、WindowsのMoveFileExWで置換します。
入れ子参照は拒否して、循環読み込みを防ぎます。
参照先欠落・未対応バージョン・無効なキーは読込失敗とし、読込先の既存データを保持します。
外側のLoadForEnemyには従来の既定値フォールバックがあるので、実際の起動時にはログも確認してください。

## 10. 二つのデータ例

- [authoring_sweep.json](../Resources/json/attack_assets/authoring_sweep.json): 表示物一つ、判定一つ。
- [authoring_double_sweep.json](../Resources/json/attack_assets/authoring_double_sweep.json): 同じ部品を時間差で二組。

どちらも専用のC++分岐はありません。「共有攻撃アセット」から割り当てて使います。
サンプルの判定は前方1.5付近なので、確認時はプロファイルの最小発動距離を0、最大発動距離を3、推奨標的距離を1.5程度に合わせて保存してください。
火球の遠距離用設定をそのまま使うと、表示は出ても近接判定が標的まで届きません。
ゲームバランスへの意図しない変更を避けるため、既定の敵攻撃はこのサンプルへ置換していません。
この二例はデータ構造と再利用の確認用で、演出品質を実機で仕上げた完成攻撃ではありません。

## 11. コード量について

敵・プレイヤーそれぞれに、表示物の生成、移動、終了、当たり判定の区間、重複命中防止を書く必要を減らします。
それらの処理は共通ランタイム側に一回置きます。
一方、今回の段階ではエディター・保存・検証の基盤を追加したため、プロジェクト全体のコード量は増えています。
既存の特殊攻撃を削除したり、全キャラクターを新形式へ移行したわけではありません。

## 12. 続く移行項目

1. 本体アニメーションの共通トラックと描画専用レイヤー、接触あり／なしで後続部品を選ぶ条件は追加済みです。[本体アニメーションと接触条件による攻撃制作](14E_本体アニメーションと接触条件による攻撃制作.md)を参照してください。骨アニメーションや手続き姿勢の全面置換は残っています。
2. ボーン／部品への親子アタッチとギズモ編集を追加する。
3. 命中、入力、終了を条件にしたセクション遷移を追加する。
4. 個別の敵とプレイヤーの攻撃を一つずつ同等性確認しながら移行し、不要になった専用C++を削除する。

## 13. 検証の境界

自動テストはJSON往復、トラックだけの再生、補間、キー境界、異常値、共有参照の更新、割り当て保持、読込失敗時のデータ保持、条件停止を扱います。
本編とプレビューは同じAttackSequenceを呼びますが、テストはGPU描画や実際のHP減少を検証していません。
実機の画面操作・見た目・ゲームプレイの確認は別途必要です。

2026-10-07の確認結果:

- Development x64のビルド成功。
- AttackSequenceTestsの既存テストと今回追加したテストがすべて成功。
- 追加ファイルのUTF-8と、本章のソース・データリンクを確認。
- 画面操作、サンプルの演出品質、実際のHP減少は未確認。
