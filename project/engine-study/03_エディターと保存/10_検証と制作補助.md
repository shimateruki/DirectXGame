# 検証、制作補助、配布まで

[目次](../00_目次と読み方.md)へ。エディターの診断表示が「実際に遊べる・配布できる」をどこまで保証するかを整理する。

## シーンとアセットの確認

Scene の保存内容は Scene Save Preview と実 JSON で確認する。依存アセットには [`ScenePreloader::Inspect`](../../engine/system/scene/ScenePreloader.cpp) のロード manifest を点検する経路がある。配置、Collider、攻撃のタイミング、プレイヤーの操作感は実際の Play で確認する。

## Asset Audit と参照追跡

[`AssetAuditWindow`](../../engine/utility/SystemDebug/editor/windows/AssetAuditWindow.cpp) はアセットの量や参照を確認する画面。[`AssetReferenceExplorer`](../../engine/utility/SystemDebug/editor/windows/AssetReferenceExplorer.cpp) は JSON の値を辿り、アセットへ向かう参照・欠落を索引化する。一般に参照グラフは「A が B を使う」という辺で考えられる。A から到達できないファイルは未使用**候補**だが、コードに文字列で書かれた動的ロード、起動時のシーン切替、デバッグ用途など、JSON スキャンに表れない利用がある。削除判断ではコード検索と実行確認を足す。

欠落参照の修復機能を使う場合も、同名アセットが意図した種類・内容かをプレビューしてから保存する。パスが有効になることと、正しい見た目になることは違う。

## LOD



[`ModelOptimizerWindow`](../../engine/utility/SystemDebug/editor/windows/ModelOptimizerWindow.cpp) はモデルの LOD 生成レポートから段階別モデルを Preview Object として配置し、採用または却下する。**LOD** は距離などに応じて詳細度の違うモデルを選び、遠方で描画負荷を下げる技術。画面上の `__Editor_LODPreview_` は比較用の仮配置で、採用操作後の Object 設定と生成ファイルを確認する。モデルの見た目だけでなく切替距離、シルエット、アニメーション対応、実ゲームの描画負荷を調べる。

## キャプチャと再現

[`CaptureToolWindow`](../../engine/utility/SystemDebug/editor/windows/CaptureToolWindow.cpp) は視覚的な問題の記録を助ける。[`ReplayDebugger`](../../engine/utility/SystemDebug/editor/windows/replay/ReplayDebugger.cpp) は時間軸上の状態再現を助ける。スクリーンショットは一時点の見た目、Replay は記録範囲内の推移を示す。バグ報告なら Scene 名、操作、発生時刻、再現条件を残すと調査が早い。Preview Stage で見えた結果なら「プレビューで確認」と書き、Play で確かめたものと混ぜない。

## テキスト生成と音声設定

[`TextSpriteGenerator`](../../engine/utility/SystemDebug/editor/windows/TextSpriteGenerator.cpp) は DirectWrite のフォント情報を扱い、テキスト PNG を生成する。Preview 画像と最終生成物を区別する。フォント名だけでは実際に選ばれたフォントファイルを保証しないため、文字形が違えば列挙・選択されたファイルと生成レポートを見る。[`AudioSettingsWindow`](../../engine/utility/SystemDebug/editor/windows/AudioSettingsWindow.cpp) の音量設定は、VFX イベントやゲーム固有の発火条件とは別。

## 配布

[`ExecutablePackageWindow`](../../engine/utility/SystemDebug/editor/windows/ExecutablePackageWindow.cpp) は実行ファイルセットを作る入口で、収集・梱包の詳細は [`Packaging`](../../engine/utility/SystemDebug/editor/windows/ExecutablePackageWindow.Packaging.cpp) にある。開発環境で起動することと、抽出した配布物が単独で起動することは異なる。必要な DLL、Shader、Model、Texture、JSON、Audio が配布物にあり、起動シーンから実際に読めるかを確認する。元の `project` と配布用コピーは分けて扱う。

## 「完了」と呼ぶための確認順

1. **静的確認**：アセット監査と参照追跡で明らかな欠落を探す。
2. **保存確認**：Scene Save Preview と実 JSON を見て、次回起動後にも値が残ることを確かめる。
3. **プレビュー確認**：VFX、アニメーション、地形、LOD など専用画面で局所的な形・時刻・設定を調整する。
4. **Play 確認**：本番シーンの入力、カメラ、衝突、音、演出順、負荷を確認する。
5. **配布確認**：生成した実行ファイルセットを別の場所へ抽出して起動する。

各段階で分かる範囲が違う。例えばビルド成功は C++ のコンパイルとリンクの確認だが、水や炎の見え方、ステージの進行、配布物の欠落までは証明しない。
