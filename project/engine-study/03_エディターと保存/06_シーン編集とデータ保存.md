# シーン編集、適用、保存

詳細解説：[Undo と保存のデータ設計](06A_Undoと保存のデータ設計.md)。

[目次](../00_目次と読み方.md)へ。この章では「見た目が変わった」から「次回起動でも残る」までを追う。

## 画面から Object まで

[`HierarchyWindow`](../../engine/utility/SystemDebug/editor/windows/HierarchyWindow.cpp) はシーン中の Object を一覧・選択する。[`InspectorWindow`](../../engine/utility/SystemDebug/editor/windows/inspector/InspectorWindow.cpp) は選択された Object の型や構成に応じた項目を表示する。3D View 上の移動・回転・拡縮は ImGuizmo を使い、Object の Transform に反映される。ここで変更されたのはまず**メモリ上の Object**。JSON が直ちに書き換わるわけではない。

Inspector の一部は型ごとの専用画面へ分割される。例えば敵、ギミック、アイテム、マテリアルの処理は `InspectorWindow.*.cpp` にある。新しいパラメータの行方を調べるときは、UI の変数、Object の setter、[`SceneSerializer::SerializeObject`](../../engine/utility/SystemDebug/editor/core/SceneSerializer.cpp) の保存キー、読込側の設定適用を一組で追う。UI だけ追加しても、再起動時に値が消えることがある。

## Scene Asset と JSON

[`SceneSerializer`](../../engine/utility/SystemDebug/editor/core/SceneSerializer.cpp) は Object を `nlohmann::json` へ変換する。`BuildSceneSaveTargets` は `SaveCategory` を見て Player / Enemy / Object / Camera などの保存対象へ振り分ける。`SaveTargets` がファイルを書き出す。`BuildSingleObjectSaveTargets` は一個の Object を対象にした保存経路。Scene Asset の作成・複製・名前変更・削除・検証も同じクラスにある。

[`SceneSavePreview`](../../engine/utility/SystemDebug/editor/windows/SceneSavePreview.cpp) は保存予定の JSON と既存 JSON を比べ、Object 単位や値の差を画面へ示す。**Preview は差分を調べる段階で、ファイル書込そのものではない。** 保存ボタンの後に `SaveTargets` が実行されたかを確認する。Scene JSON の `SaveCategory` は保存先を分ける情報であり、実行時の継承階層を示すものではない。

Scene Asset とファイルパスの対応を探すには [`SceneWorkspace`](../../engine/utility/SystemDebug/editor/core/SceneWorkspace.cpp) と [`ProjectWindow`](../../engine/utility/SystemDebug/editor/windows/ProjectWindow.cpp) を読む。Scene Workspace の視点ブックマークは編集時の作業補助で、Play 中のカメラ位置をそのまま保存しない処理がある。

## プリセットと Asset Database

[`AssetDatabase`](../../engine/utility/SystemDebug/editor/core/AssetDatabase.cpp) はエディターが参照するアセットを索引化する。[`PresetManager`](../../engine/utility/SystemDebug/editor/core/preset/PresetManager.cpp) と [`PresetEditor`](../../engine/utility/SystemDebug/editor/core/PresetEditor.cpp) は再利用する設定の登録・編集に関わる。プリセットを Object に適用すること、プリセット自体を保存すること、Scene を保存することは別操作。どこへ値が書かれたかを確認してから画面を閉じる。

[`EditorPropertyRegistry`](../../engine/utility/SystemDebug/editor/core/EditorPropertyRegistry.cpp) はエディター用に編集可能なプロパティの情報を管理する。[`EditorPropertyDrawer`](../../engine/utility/SystemDebug/editor/core/EditorPropertyDrawer.cpp) は値の型に応じた UI を描く。[`EditorPropertyTransaction`](../../engine/utility/SystemDebug/editor/core/EditorPropertyTransaction.h) は変更を履歴へまとめる側。これは一般的な**メタデータ駆動 UI**で、個別 Inspector に毎回同じ DragFloat 等を手書きする部分を減らす。実際の保存経路は対象 Object と Serializer の実装も確認する。

## Undo / Redo とバックアップ

[`EditorTransactionManager`](../../engine/utility/SystemDebug/editor/core/EditorTransactionManager.cpp) は Undo / Redo のスタックを持ち、操作の前後をまとめる Group と連続操作を一回へまとめる対話的トランザクションを扱う。Undo は現在の編集セッションでの操作を戻す機能。ディスク上の過去の JSON 版を検索する機能ではない。

保存後は Scene Save Preview と実 JSON を確認する。未保存の Inspector 値はファイルへ反映されていないため、シーン切り替えやアプリ終了前に保存状態を確かめる。

## Play 中の変更と復元

Play はゲーム側が Object を更新するため、編集値と実行時値が混ざりやすい。[`PlayModeChangeTracker`](../../engine/utility/SystemDebug/editor/core/PlayModeChangeTracker.cpp) は Play 開始時の基準状態と停止前の状態を比べ、編集可能な Object の変更候補を表示する。Player / Enemy / Item / Bullet 等は対象から除外され、実行時に動くギミックの Transform も条件に応じて除外される。利用者が選んで持ち帰った変更は Undo に登録される。候補一覧は一時データであり、Scene JSON の保存とも Replay の記録とも別。

## 値が消えたときの追い方

1. UI の値を変えた直後、選択 Object の getter が新しい値か確認する。
2. Play の開始・停止で値が戻ったなら、Play 用の復元と持ち帰り候補を確認する。
3. Scene Save Preview に該当 Object / キーが出るか確認する。
4. 保存後、実際の JSON キーと値を見る。
5. 再読込で値が変わるなら、Serializer の書き出しと Scene 読込側の適用を両方見る。

この順にすれば、「画面の更新」「実行時の変更」「ファイルへの保存」「読込」を混同しない。
