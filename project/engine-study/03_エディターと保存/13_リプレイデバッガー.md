# Replay Debugger の記録と再生

[目次](../00_目次と読み方.md)へ。ここは「ゲームで起きたことを後から調べる」ための専用章。[アニメーション・演出](../02_描画と演出/07_アニメーション演出リプレイ.md)は作る側の時間、Replay は観測する側の時間を扱う。

## 何を記録するか

[`ReplayDebugger.h`](../../engine/utility/SystemDebug/editor/windows/replay/ReplayDebugger.h) の `FrameSnapshot` は Object、Sprite、Camera、Scene 固有状態などをまとめる。各 Object は `CaptureReplayState` で自身の状態を渡す。これは Scene JSON の保存形式と同一ではない。Scene JSON は次回ロードのための設定、Snapshot はその時点の実行状態を復元・比較するためのデータ。

現在の既定 `captureRate_` は 15 fps。毎ゲーム更新で Input の Replay State をサンプルする一方、Object 状態はその設定間隔で間引いて保持する。[`CaptureAfterSimulation`](../../engine/utility/SystemDebug/editor/windows/replay/ReplayDebugger.cpp) を見ると、この二つの粒度の違いが分かる。**「入力を毎更新記録する」ことと「全状態を毎更新保存する」ことは別**。録画時間が増えれば Snapshot のメモリ費用も増えるため、時間の細かさと費用を調整する設計。

## フレーム内の位置

[`GameEditorController::UpdateTools`](../../engine/core/editor/GameEditorController.cpp) から Replay の `UpdateBeforeSimulation` を呼び、ゲームシミュレーション後に `CaptureAfterSimulation` を呼ぶ。再生側は更新前に記録状態を反映し、記録側は更新後の結果を採る。この前後関係がずれると、入力と結果が 1 更新分食い違って見える。

シーンが切り替わると `SceneManager` の世代を検証し、別シーンの Object ポインタを使い続けないよう記録をリセットする。Replay が有効な場面と、シーン遷移中の制約は [`ReplayDebugger.cpp`](../../engine/utility/SystemDebug/editor/windows/replay/ReplayDebugger.cpp) の `GetValidatedActiveScene` と `ResetForSceneChange` を追う。

## 再生位置を動かすと何が起きるか

UI のスライダーが動くだけでは再現にならない。Replay は対象 `FrameSnapshot` を探し、**Scene 固有状態を先に**、その後で Object、Sprite、Camera の個別状態を復元する。順序があるのは、Scene の状態が Object へ影響する場合に逆順だと上書きが起こりうるため。見た目の確認と、記録 Input を使った回帰比較の経路も分かれる。保存済み Replay の読込と継続可否は [`Archive`](../../engine/utility/SystemDebug/editor/windows/replay/ReplayDebugger.Archive.cpp) と `CanResumeLoadedArchive` を参照する。

[`Regression`](../../engine/utility/SystemDebug/editor/windows/replay/ReplayDebugger.Regression.cpp) は期待するフレームと実行結果を比較する経路。比較対象へ含まれない乱数、非同期ロード、外部アセットの変更まで完全一致を保証するものではない。失敗時はタイムライン上の最初の相違と、その前に起きた Input / Scene Event を追う。

## Play 前の状態を守る仕組み

`BeginPlayInEditorSnapshot` は Play を始める前の編集状態を記録し、`RestorePlayInEditorSnapshot` は停止時に同じ Scene へ戻す。Play 中に生成された Object や Sprite の扱いも復元側にある。この機構は**編集状態の一時保護**であり、Replay Archive の保存とは違う。[`PlayModeChangeTracker`](../../engine/utility/SystemDebug/editor/core/PlayModeChangeTracker.cpp) は、Play 中に意図的に変えた編集可能な設定を選んで持ち帰る別の機能。復元と持ち帰りを同時に理解するには、停止時にどちらが先に動くかを見る。

## 操作別の読み方

| 操作 | 呼び出しとデータ | 期待できること |
| --- | --- | --- |
| 録画開始 | `BeginRecording`、最初の `CaptureFrame` | 初期状態を基準として残す。 |
| Play 中 | `CaptureAfterSimulation`、Input State | 入力と間引いた状態を時間軸へ追加。 |
| Pause / Seek | 記録済み `FrameSnapshot` の選択・適用 | 記録時点の状態を調査する。 |
| Archive 保存 | `SaveCurrentReplayArchive` | 後で読み込むために記録をファイル化。 |
| 回帰確認 | `CompareRegressionFrame` | 記録と現在実行の相違を検出。 |
| Play 停止 | `RestorePlayInEditorSnapshot` | 編集前状態へ戻す。 |

エディターの Undo は操作履歴、JSON Backup は保存ファイルの退避、Replay は実行状態の時間軸。三つを同じ「巻き戻し」と呼ばない方がトラブル調査で混乱しない。
