# 素材画像と共通追尾部品で攻撃を組み立てる

## 1. 目的と今回の範囲

攻撃のたびに「エフェクトを読む」「標的へ向ける」「移動する」「判定位置も動かす」をC++で書く工程を減らします。
素材JSON、動作の設定、表示に追従する判定を、攻撃データへまとめます。

今回追加したものは次の四つです。

1. MeshEffect素材の画像付き選択と名前検索。
2. 共通動作の「照準して直進」「照準して追尾」。
3. 表示Objectを親とする判定部品。
4. 共通enemy攻撃候補の優先度・均等ランダム・重み付きランダム選択。

対象は既存のAttackSequenceを呼ぶ接続先です。既存ボスの特殊攻撃を全置換する変更ではありません。
第二形態のカメラ演出やGhost Directorのカメラ制御には手を加えていません。

## 2. 最初に操作する場所

配置確認と再編集の操作は [14G](14G_攻撃エディターの配置確認と再編集.md) にまとめています。

1. 敵攻撃プレビューで炎スライムを選ぶ。
2. 左側の「新しい攻撃を作る・見本から始める」を開き、「照準・発射・追尾の例から作成」を押す。
3. 「追尾する表示Object」を選ぶ。
4. 右側の「表示プリセット」を開く。素材名で検索し、画像を見ながら選ぶ。
5. 「共通動作」でキー移動・直進・追尾を選ぶ。
6. 発射までの時間、移動速度、狙う高さ、旋回速度、追尾時間を調整する。
7. 表示Objectに判定を付ける場合は「このObjectに判定を追加」を押す。
8. 左側に字下げされた判定を選び、半径、威力倍率、開始・終了を調整する。
9. 左の「保存して再生」で、保存したデータを使うプレビューを再生成する。

サンプルの構成は次です。

```text
追尾する表示Object      0.0～2.5秒
  照準                 0.0～0.5秒
  発射後に追尾         0.5～1.7秒
  最後の方向へ直進     1.7～2.5秒
  └ 表示Objectに追従する判定 0.5～2.5秒
```

移動速度は4、旋回速度は100度/秒です。これは共通動作と親子の接続を確認する制作例で、既存の槍攻撃を同じ見た目・挙動で移植したものではありません。
素材は既存のMeshEffectを流用しています。槍などの別モデルを使うにはMeshEffect Editorでそのモデル・材質を設定した素材を保存し、表示プリセットで選びます。

## 3. 「JSONを読むだけ」の中で何が起こるか

保存するJSONは、C++の機能を選んで設定するデータです。

```text
攻撃JSON
  ├ 表示素材のパス → EffectObject3dの生成
  ├ motion         → 共通の動作部品
  ├ 時間と速度     → 動作部品へのパラメーター
  ├ parentTrack    → 表示と判定の接続
  └ condition      → 部品を開始する条件
```

共通の読み取り・実行処理を一度C++で作ることで、新しい攻撃ではこの組み合わせを保存できます。
今回は壁回避、地面の経路探索、跳弾などの動作部品は追加していません。そのような新しい仕組みが必要な場合は共通部品側の実装が必要です。

## 4. 素材の画像をどう作るか

既存のProjectWindowはモデル・プリセット・PBRの撮影先を持っています。
今回はそのサムネイルキャッシュと撮影ループにMeshEffect用の経路を追加しました。

1. 素材選択UIが画像を要求する。
2. 未生成なら、撮影待ちとしてキャッシュへ登録する。
3. 描画開始時の`CapturePendingThumbnails`が撮影用EffectObject3dを生成する。
4. 実際の素材JSONを読み込む。
5. 寿命の40%の時点へ更新する。開始直後の空画像を避けるための代表時刻。
6. モデルの寸法と現在の拡縮から、撮影範囲へ収まる倍率を計算する。
7. 小さなRender Targetへ描画し、そのSRVをImGuiの画像として表示する。

**Render Target**はGPUが画像を書き込むテクスチャです。**SRV**はその画像をシェーダーから読み取るための参照です。
書き込み時は`RENDER_TARGET`、UIからの参照時は`PIXEL_SHADER_RESOURCE`へResource Barrierで切り替えます。

既存の上限96件のプリセットキャッシュを共有し、撮影はプリセットと合わせて1フレーム4件までです。
一覧では画面内の画像だけ要求します。全素材を毎フレーム生成・更新する構成にはしていません。
再撮影時の古い描画ObjectはGPUのFence完了まで保持し、まだGPUから参照されているバッファを即座に破棄しないようにしています。

### 撮影と本編の分離

撮影用ObjectはゲームのObjectManagerへ登録しません。衝突属性・マスクを0にし、対象追従も無効にします。
背景歪みは素材一覧に本編の背景がないため無効化し、色と形を撮影します。
複数板のVolumeModeなどMeshEffectManager側が組み立てる追加構造は、この一体の撮影Objectには含まれません。
このためサムネイルは素材を見つける補助で、本編と完全に同じ画面合成を保証するものではありません。

### 現段階の制約

- 画像付き選択の対象はMeshEffect素材です。GPU粒子・アニメーション・攻撃全体の動画プレビューは未追加です。
- 静止画なので、発生から消えるまでの動きは攻撃プレビューで確認します。
- 代表時刻が素材の見せ場と一致しない場合があります。
- 元JSONを別エディターで編集した場合は「素材を撮り直す」で更新します。
- タグ・お気に入り・全素材のGUID参照への移行は未実施です。

## 5. 共通動作のデータ

表示トラックに次の項目を保存します。

| 項目 | 意味 |
| --- | --- |
| motion | `keyframed`、`aim_launch`、`homing` |
| launchDelay | 部品の開始から発射するまでの秒数 |
| moveSpeed | ワールド空間を進む速度。UI上の単位はm/s |
| turnDegreesPerSecond | 追尾中の旋回角度の上限。度/秒 |
| homingDuration | 発射後、標的へ旋回する秒数 |
| targetHeight | 標的の原点に加えるワールド上方向の高さ |

`keyframed`は以前からある位置キーの再生です。
`aim_launch`と`homing`は先頭キーの位置へ生成し、その後の位置を動作部品が所有します。位置キーを足しても飛行経路にはなりません。
回転・拡縮のキーは表示に使用します。進行方向の基準はモデルの+Zです。違う軸を前に作った素材は回転キーで合わせます。

初期位置は術者の右・上・前からワールドへ変換します。生成後はその地点に留まり、発射を待ちます。
キー再生用の「術者に追従」は、飛行Objectを毎フレーム術者へ引き戻す設定ではありません。

## 6. 照準・直進のロジック

発射前は、対象が存在する場合に次の方向を更新します。

```text
aim = targetPosition + (0, targetHeight, 0) - objectPosition
direction = normalize(aim)
```

標的と同じ位置で長さが0になる場合は、直前の方向を維持します。
発射時に照準を固定し、直進モードでは以降の標的位置を使いません。

```text
position += direction * moveSpeed * step
```

標的を失った場合も最後の方向へ進みます。消滅や別対象への再検索は今回の部品に含めていません。
Actor本体の移動・物理速度を変更する部品ではなく、攻撃が所有する表示Objectの移動です。

## 7. 追尾と旋回速度制限

現在の進行方向を`d`、標的方向を`t`とします。どちらも単位ベクトルです。
内積から両者の角度を求めます。

```text
angle = acos(clamp(dot(d, t), -1, 1))
turn = min(angle, 旋回速度のラジアン値 * step)
```

標的方向から現在方向に平行な成分を取り除くと、旋回する方向の接線が得られます。

```text
tangent = normalize(t - d * dot(d, t))
newDirection = normalize(d * cos(turn) + tangent * sin(turn))
```

これにより標的へ瞬間的に向き直らず、設定した角速度の範囲で曲がります。
標的が真後ろにあると接線が0になるため、現在方向と直交する代替方向を選びます。
追尾時間が終わると旋回を止め、最後の方向を維持します。

計算は最大1/120秒の小区間に分割します。これは**サブステップ積分**です。
大きなdtを一回だけ掛ける場合より、曲線移動の誤差を抑えます。追尾終了時刻でも区間を分割します。
ただし標的位置はそのUpdate呼び出しで受け取った値です。過去の標的軌道を再構成したり、全フレームレートで完全一致させたりする仕組みではありません。

## 8. 表示Objectと判定の接続

判定トラックの`parentTrack`に、表示トラックの配列番号を保存します。
親の現在位置と方向を参照し、その位置へ判定キーのオフセットを加えます。
判定の半径は親の表示スケールと独立しており、勝手には拡大しません。
オフセットの右・前は水平方向を基準とし、上はワールド上方向です。任意の傾き・ロール・ボーンを継承する一般的な親子行列ではありません。

次の構成は保存時に拒否します。

- 判定が自分自身や後ろの部品を親にしている。
- 親が表示Objectではない、または無効。
- 判定区間が親の存在する区間からはみ出す。
- 親を削除した後、参照先が未修正。

配列の前の表示Objectだけを参照するため、循環参照ができず、同時刻の更新でも親から先に評価できます。
親が条件不成立で出現しなかった場合、子の判定も問い合わせません。
左側では子の判定を字下げして示します。現在は表示と判定の一段の関係で、任意深さのObjectツリーではありません。

### 衝突の精度と寿命

各更新で前の位置から現在位置まで球／カプセルの問い合わせを行います。
判定が初めて有効になる更新でも、親の直前位置を参照して通過区間を求めます。
一更新内で曲がった軌道や判定開始時刻の位置は近似を含みます。厳密な連続衝突判定ではありません。
同じ判定トラックから同じ対象への通知は一再生につき一回です。
接触しても表示Objectは寿命まで進みます。接触時に飛行体そのものを破棄する設定や、地形への衝突停止は未追加です。

## 9. 攻撃候補の選択

プロファイル側の`selectionMode`を保存します。共有攻撃アセットではなく利用する敵側の設定です。
各攻撃の`selectionWeight`もプロファイル側へ保存します。

| 方式 | 選び方 |
| --- | --- |
| priority | 既存どおり、候補の最大優先度。同値なら先頭 |
| uniform | 条件を満たす候補から同じ確率で選ぶ |
| weighted | 各候補の重みを合計で割った確率で選ぶ |

候補になるのは、シーケンスが有効・bindingがenemy・射程内の攻撃です。炎スライムでは検知範囲も使います。
重み付きで0の候補は除外します。均等ランダムでは重みを使いません。
プレビューで指定した攻撃は、重み0でも確認できるよう抽選より優先します。ただし射程条件は残ります。

例えば、射程内の候補が重み3と1なら、確率は75%と25%です。
重み3の攻撃が射程外になると、残る重み1の攻撃が100%になります。固定の全体確率として解釈しないでください。
現在のUIは重みの入力までで、距離ごとの確率一覧はまだありません。

### 接続先による違い

- 炎スライム：共通攻撃の候補選択をこの方式へ接続。従来のブレスなど専用処理は残っています。
- プリズム：FireFan系へ入ったときの共通攻撃候補に適用。属性フェーズ、召喚、晶槍など外側の行動サイクルは既存C++です。
- プレイヤー：入力で攻撃するため、この敵向け抽選設定は適用しません。また現在の炎コピーのContextには標的が渡らないため、この追尾部品は前方へ直進します。

均等／重み付きでプリズムの候補が空の場合は、重み0の旧火球へ戻さず、外側のサイクルを次へ進めます。
連続使用禁止、HP条件、候補ごとの独立クールダウン、乱数状態のReplay保存は今回追加していません。

## 11. 次に残る制作機能

今回の改良は共通動作を選ぶ工程を実装したものです。攻撃制作環境全体が完成したわけではありません。
一般のモデル／Prefab／GPU粒子を統一した素材ブラウザー、ギズモからのキー記録、任意深さの親子構成、既存の槍攻撃の同等性を確認した移植は残っています。
Ghost Directorの編集機能をそのまま全面統合した状態でもありません。
既存の専用C++を減らすのは、移行対象ごとの見た目・タイミング・衝突・終了条件を比較した後です。

## 12. 検証の境界

自動テストは実行時にも使うAttackMotionStateとSelectSequenceを呼びます。
照準固定、旋回速度上限、真後ろ・標的消失、追尾終了、親子参照の不正値、JSON往復、重み付き比率、均等抽選境界、射程除外を検証します。
素材画像の見た目、エディターの実操作、移動する標的への追尾、実際のHP変化は実機で別途確認が必要です。

- 最後の増分ビルドは約2.6秒で完了し、C++の再コンパイルなし。
- 既存テストと今回追加したMotion/selectionテストがすべて成功。
- 変更ソース・新規JSONのUTF-8と、本章のファイルリンクを検査。
- 実画面のサムネイル表示、操作、HP変化、演出品質は未確認。
