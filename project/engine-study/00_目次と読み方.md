## 最初に区別する三つの境界

**画面に適用した値とファイルに保存した値は違います。** Inspector で Object のプロパティを変えても、それだけで Scene JSON が更新されたとは限りません。[`SceneSerializer`](../engine/utility/SystemDebug/editor/core/SceneSerializer.cpp) と [`SceneSavePreview`](../engine/utility/SystemDebug/editor/windows/SceneSavePreview.cpp) が保存側です。

**プレビューと実際の Play は違います。** VFX Preview Stage や Animation Workbench は専用の対象・時計・再構築処理を使います。敵 AI、当たり判定、地形との相互作用をすべて再現する証拠にはなりません。

**Undo と Backup と Replay は違います。** Undo は編集操作の履歴、Backup は保存ファイルの退避、Replay はゲーム状態を時間軸上に記録する仕組みです。戻せる対象と保存先が異なります。

## この資料の読み方

各章は原則として **利用者の操作 → 保持するデータ → 呼ばれる処理 → GPU/CPU の技術 → 見た目または保存結果 → 制約** の順に説明します。`技術名` は現行コードで確認できたものだけを書きます。たとえば炎に「レイマーチング」を使う実装はありますが、すべての炎や雲が同じ方法とは書きません。

コードへのリンクはこの資料からの相対パスです。実装が変わった場合、まずリンク先の関数と呼び出し側を確認してください。章末の「別の方法」は学習用の比較であり、現行実装の説明ではありません。


コメント・空白の全型再点検は[全クラスコメント再点検](16_全クラスコメント再点検.md)に対象一覧と検証結果を記録しています。
