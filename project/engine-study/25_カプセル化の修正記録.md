# カプセル化の修正記録

[目次](00_目次と読み方.md) / [前回の調査](17_全クラスのカプセル化調査.md)

## 今回の判断

2026-10-09 のソースを確認し、**基底クラスの内部状態を派生クラスから直接変更できる箇所**を整理した。使用箇所を調べてからアクセス範囲を変え、位置・回転などの変更は既存の操作 API に移した。公開フィールドを機械的にすべて隠すと、Editor や派生クラスの実装を壊すため、実際に継承先が使用する値と編集データは理由を記して残した。

## 修正した内容

| 対象 | 変更 | 変更の理由 |
| --- | --- | --- |
| [`Object3d`](../engine/graphics/3d/object/Object3d.h) | `transform_`、名前、アニメーション時刻、レンダラー、コンポーネント、Replay 状態など、従来一つの `protected` 範囲に置かれていた内部状態を `private` にした。 | 派生クラスが状態を書き換える際、専用の操作を通るようにする。 |
| `Object3d` の派生クラス向け操作 | アニメーションを先頭へ戻す `ResetAnimationTime()` と、複製時に行列・外部アンカーも含めて姿勢をコピーする `CopyTransformStateFrom()` を `protected` に設けた。 | 生のメンバーを開かず、従来のアニメーション再開と `Character::Clone()` の複製内容を保つ。 |
| [`Character`](../game/actor/Character.h) | 外力の速度・残り時間などと `CharacterMotor` を `private` にした。移動・衝突補正はローカルの位置を Motor に渡し、結果を `SetTranslate()` で反映する。 | 外力の管理と Motor の実行状態は `Character` 自身だけが扱っているため。 |
| [`BaseEnemy`](../game/actor/enemy/core/BaseEnemy.h) | 被弾色の復帰タイマー、休止フラグ、投擲物理フラグを `private` にした。 | これらは基底クラスの処理だけで使われ、派生敵の拡張口ではないため。 |

直接参照を置き換えた主な呼び出し側は [`Bullet`](../game/actor/Bullet.cpp)、[`Player`](../game/actor/player/Player.cpp)、[`PlayerClone`](../game/actor/player/clone/PlayerClone.cpp)、[`EnemySlime`](../game/actor/enemy/normal/EnemySlime.cpp)、[`EffectObject3d`](../engine/graphics/effect/EffectObject3d.cpp) である。`Player` の Euler 角と Quaternion の同期は、`SetEulerAngles()` と `SetQuaternion()` の順に呼び、以前と同じく Quaternion を主表現に保つ。

## 意図を確認して残した公開範囲

| 対象 | 残した理由 |
| --- | --- |
| `Object3d` の Replay 用仮想関数 | 派生クラスが固有の状態を記録・復元するための拡張口。 |
| `Object3d::common_` | 派生オブジェクトが自分の分身や演出オブジェクトを生成するとき、同じ描画環境を渡す用途が複数ある。借用ポインタの継承契約として残した。 |
| `Character::velocity_` と `isGrounded_` | 敵や Player の派生クラスが移動・ジャンプ・着地判定で直接使用している。物理状態の操作 API へ統一するには別途、各挙動の検証が必要。 |
| `BaseEnemy` の追跡対象、検知距離、攻撃設定など | 複数の敵派生クラスが AI と演出に使用している。今回使われない状態だけを閉じた。 |
| `EffectObject3d` の公開 `edit..._` 設定 | MeshEffectEditor、プリセット読み込み、攻撃生成が編集値を直接扱う既存の制作経路。設定型と適用 API を設計してから移す必要がある。前回の調査で指摘した値の検証・GPU マテリアル更新の課題は残る。 |

`private` 化したのは、派生先から使われない状態と、既存の操作へ安全に移せる状態である。可変ポインタ・可変参照を返す API は別の公開経路なので、この変更だけでカプセル化がすべて完了したという意味ではない。[前回の調査](17_全クラスのカプセル化調査.md)の中優先項目は引き続き有効である。

## 検証と残る実操作

最終コードで `DirectXGame.vcxproj` を MSBuild の直列実行（`/p:MultiProcessorCompilation=false /m:1`）で確認した。

| 構成 | 結果 | 出力先 |
| --- | --- | --- |
| Development x64 | コンパイル・リンク成功 | `C:\二年前期\CG2\generated\outputs\EncapsulationCheck2\DirectXGame.exe` |
| Debug x64 | コンパイル・リンク成功 | `C:\二年前期\CG2\generated\outputs\Debug\DirectXGame.exe` |

ビルドはアクセス制御とリンクの確認であり、Editor 操作やゲーム中の動作確認とは区別する。次の実操作は未実施である。

- Character の複製後の位置・姿勢、外部アンカー、モデル表示。
- Player の移動、コピー能力中の見た目、アニメーションの再開。
- Bullet の高速移動と衝突位置、敵の着地・投擲・被弾色復帰。
- Editor の Transform 変更、Undo、保存・再読込、Replay 復元。
