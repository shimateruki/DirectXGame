# 水と局所霧：式から見た目まで

[目次](00_目次と読み方.md) / [シェーダー概要](03_シェーダーとマテリアル.md) / [体積炎](03A_体積炎のレイマーチング.md)

同じ「透ける立体的な見た目」でも、水面、局所霧、体積炎では計算が異なる。この章は [`Water.PS.hlsl`](../Resources/shader/materials/Water.PS.hlsl) と [`LocalFog.PS.hlsl`](../Resources/shader/materials/LocalFog.PS.hlsl) を読むためのノートである。特に霧は炎のように視線上を何十回もサンプリングする実装ではない。

## 1. 水面の色は一枚の青いテクスチャだけで決まらない

水面シェーダーは、背景色、背景深度、水面位置、視線方向、波による法線、光方向などを組み合わせる。読み順は次の通り。

```text
波の傾き → 法線
背景深度 → 水底位置 → 水の厚み
傾き → 背景の参照 UV をずらす
厚み → RGB ごとの透過率
視線と法線 → Fresnel による反射率
光と法線 → ハイライト
浅い交差部分 → 泡
背景と合成 → 最終色
```

波の形を決める頂点側と共通式は [`Water.VS.hlsl`](../Resources/shader/materials/Water.VS.hlsl)、[`Water.hlsli`](../Resources/shader/common/Water.hlsli) も参照する。輪郭の上下動と表面の細かい光の揺れは、同じ解像度で計算する必要がない。細部まで頂点を増やす代わりに、ピクセル側で法線を揺らして表現できる。

## 2. 深度から水底の位置を復元する

深度テクスチャの値は、そのままメートルやワールド距離ではない。画面座標を NDC へ変換し、深度と組み合わせた位置へ逆 ViewProjection 行列を掛け、w で割ることで背景のワールド位置を得る。この射影の逆変換は、水面と背景の間隔を同じ空間で比較するために必要である。

現行コードは水面と復元した背景位置の距離を `thickness` として使う。一方、浅瀬の色分けには垂直方向の深さも関係する。視線方向の厚みと垂直の深さを混同すると、斜めから見た色の変化を説明できない。

深度に水底がない場合は代替の厚みを使う。画面に描かれた背景の深度しか持たないため、水中の全地形や画面外の構造を再構築しているわけではない。

## 3. 屈折は背景画像の UV をずらす

屈折（Refraction）は物理的には境界を通る光線の方向変化である。このコードは、水面の傾きなどから画面 UV のずれを作り、取得済みの背景画像をずらして参照する Screen-space Refraction の近似を使う。

背景の石がゆがむのは、その画素で別の背景位置を読むためである。水中の三次元光線を追跡して新しい交点を求めてはいない。背景画像に存在しない画面外の情報、前後関係の複雑な境界はこの方法の制約になる。

## 4. Beer–Lambert 型の吸収：厚いほど赤が消える

コードでは RGB ごとの透過率を指数関数で計算する。基礎形は次の式である。

```text
T = exp(-吸収係数 × 厚み / depthRange)
```

ある分岐の係数は `(3.8, 1.35, 0.62)`。厚み / depthRange が 1 なら透過率はおよそ `(0.022, 0.259, 0.538)` になる。赤が強く失われ、青は比較的残る。そのため厚い水を通して背景を見ると青緑寄りになる。

これは物理式の形を使った調整可能な表現であり、係数が現実の特定の水質を測定した値という意味ではない。`depthRange` を変えると「どの厚さで暗く・深くなるか」が変わる。水底色そのものを変える操作とは効果が違う。

## 5. Fresnel：見る角度で反射を変える

Schlick 型の近似は次の形になる。

```text
F = F0 + (1 - F0) × (1 - N・V)^5
```

N は水面法線、V は視線方向。コードにある水の基準値は `F0 = 0.02037`。正面から見て N・V が 1 なら反射は小さく、すれすれの角度で N・V が 0 に近づくと反射が強くなる。

真上から見ると背景の透過や水の本体色が重要になり、低い角度では空の映り込みが重要になる。真上からの水らしさを反射率だけで解決しようとしても、正面で反射を弱くする式と競合する。

反射色は `SkyRadiance(reflect(-view, normal))` から得る。現行関数は方向から空の色や雲の模様を作るもので、周囲の全 Object を反射する SSR やレイトレーシングではない。物体が映っていない場合に、反射強度の調整だけでその物体を出すことはできない。

## 6. 微細な波とハイライトのちらつき

ピクセル内に収まらないほど細かい波をそのままサンプルすると、カメラ移動で模様が突然反転したり、明るい点がちらついたりする。これはサンプリングの問題である。

コードは `ddx` / `ddy` などで画面上の変化量を見て、高周波の傾きを弱め、解像できなかった傾きの分散を粗さへ反映する。`roughness * roughness + ripples.z` のような項がその接点になる。細部を単に消すだけでなく、平均的に広がった反射へ置き換える考え方である。

ハイライトには法線分布・幾何減衰・Fresnel の項を組み合わせた microfacet 型の式がある。ここで roughness は表面の細かな法線のばらつきを表す調整値で、頂点の波高そのものではない。波高を変えずに反射だけ広げることができる。

## 7. 上から見える模様と接触泡

現行水面には低・中・高周波の動く面模様を合成する、見た目を設計した処理もある。これらを「水底に光線が集まるコースティクスの物理計算」と呼ぶのは正確ではない。水らしい大きな色面と流れを上からも読めるようにする表面の模様である。

泡は背景深度が存在することを確認し、`thickness` が小さい領域へ付ける。`foamWidth` は接触帯の幅、時間で動く信号は泡の切れ目、`fwidth(thickness)` は画面上の境界をなめらかにする幅の目安として使われる。

水面と物体の間隔が小さいほど泡が出るため、水位や物体配置も泡の出方を変える。泡テクスチャをどこにでも重ねる方法とは異なる。一方で、波が実際に砕けた場所を流体計算で求めているわけでもない。

最終出力は `lerp(original, result, color.a)` を色として返し、出力 alpha は 1 である。`color.a` はここでは背景と計算結果の混合量としてシェーダー内で消費される。「alpha が 0.5 だから後段の通常の半透明合成だけで透ける」と読むと、合成を二重に理解してしまう。

## 8. 局所霧：箱は密度領域の境界

局所霧の箱は最終的に箱の面を見せたいわけではなく、霧が存在する領域を表す。シェーダーはカメラと背景位置を箱のローカル空間へ変換し、`[-0.5, 0.5]` の箱と視線を交差させる。

使うのは slab 法による Ray–AABB 交差である。X、Y、Z それぞれで箱の範囲に入る時刻と出る時刻を計算し、最も遅い入場時刻を tEnter、最も早い退場時刻を tExit とする。入場が退場より遅ければ、三軸の区間が同時に重ならず交差していない。

開始は `max(tEnter, 0)`、終了は箱の出口と背景位置の近い側を使う。これにより壁の向こうにある霧まで手前へ重ねることを避ける。開始と終了をワールドへ戻して距離を測るので、箱の拡大縮小後の厚みを色の濃さへ反映できる。

## 9. 霧の不透明度とノイズのサンプル位置

基本の霧量は `1 - exp(-thickness * fogDensity)`。密度 0.2、厚み 1 なら約 0.181、厚み 5 なら約 0.632 になる。厚みを二倍にしても alpha が単純に二倍になるわけではなく、1 に近づく飽和がある。

その後、視線区間の中点を使って箱の端と上部のフェードを計算する。ノイズも中点で二つのスケールを取り、`0.6 * n1 + 0.4 * n2` と合成する。ノイズ座標を時間で動かすため、密度の模様が流れて見える。

ノイズは格子点のハッシュ値を三次元補間する value noise。二つの周波数を加える構成であり、速度場や圧力を更新する流体ソルバーではない。そして視線区間の中点で代表させるので、奥行き方向に何層もの濃淡を積分する炎のレイマーチングとも違う。

この近似はサンプル数を抑えられるが、視線上に複雑な密度分布がある場合を正確に表現しない。厚みの式が正確でも、すべてのノイズ密度を積分した光学的厚みになるわけではない。

## 10. 光の方向で明るくする位相関数

コードの位相項は Henyey–Greenstein 型である。

```text
phase = (1 - g²) / |1 + g² - 2g cosθ|^(3/2)
```

cosθ は視線方向と光方向の関係、g は方向への偏りを調整する。g が 0 ならこの式の phase は 1 で方向差がなくなる。g を変えると、光を見る向きに応じた霧の明るさが変わる。

現行式は正規化係数 1/(4π) を含めず、`scatteringIntensity` で強さを調整している。霧の中で光を何度も散乱させる計算や、各地点から光源へ遮蔽物を調べる計算まで含むわけではない。`fogColor + lightColor * phase * scatteringIntensity` が最終 RGB の基礎になる。

## 11. 三つの表現を選ぶときの違い

| 表現 | 奥行きの扱い | 主な計算 | 得意な見た目 |
| --- | --- | --- | --- |
| 水面 | 表面と画面内背景の間隔 | 背景 UV、吸収、Fresnel、反射、泡 | 波でゆがむ背景、角度で変わる反射 |
| 局所霧 | 箱を通る厚みと中点 | 指数減衰、中点ノイズ、位相項 | 地面付近の薄いもや、領域的な霞 |
| 体積炎 | 箱内部を複数点サンプル | 密度、発光色、前からの透過率蓄積 | 奥行き方向に重なる発光密度 |

どれも画面結果は三次元的に見えるが、その内部モデルと負荷は異なる。見た目を調整するときは、欲しい変化に対応する項を選ぶ。炎の細部不足を霧の密度値で解決する、といった対応にはならない。
