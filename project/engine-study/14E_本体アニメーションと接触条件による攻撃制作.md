# 本体アニメーションと接触条件による攻撃制作

追加の素材画像・共通追尾・攻撃候補の抽選については[次の章](14F_素材画像と共通追尾部品で攻撃を組み立てる.md)を参照してください。

## 1. 今回、操作として何が増えたか

前の段階では、攻撃の表示物と球形の攻撃判定を、別々の時間区間として追加できました。
今回は、その攻撃に「キャラクター本体を変形させるアニメーション」と「先の判定結果に応じて後続を出す条件」を追加しました。

たとえば次の構成を、攻撃ごとのC++分岐を追加せず保存できます。

1. 開始時に身体を縮め、伸ばすアニメーションを再生する。
2. 0.1～0.4秒だけ前方に攻撃判定を出す。
3. その判定が対象に接触した場合、0.6秒から二段目の表示と判定を出す。
4. 接触しなかった場合は、0.6秒から空振りのリカバリー姿勢を再生する。
5. 攻撃時間が終わったら、攻撃が所有する表示と本体の追加姿勢を解除する。

現在この共通ランタイムを呼ぶのは、炎スライムの共通攻撃、プリズムスライムの対応する共通攻撃、プレイヤーの炎コピーの特殊攻撃です。
ほかの敵・能力まで自動的に移行したわけではありません。

## 2. 最初に試す操作

1. 敵攻撃プレビューで炎スライムを選ぶ。
2. 左側の攻撃制作用Hierarchyで「本体の動き＋接触分岐の例から作成」を押す。
3. 新しい攻撃が追加される。元の攻撃を置き換える操作ではない。
4. 左側の「本体の溜めと解放」を選び、右側でクリップ・再生速度・開始位置・ブレンドを確認する。
5. 「斬撃表示 2」か「斬撃判定 2」を選ぶ。開始条件が「指定判定の終了後: 接触あり」、参照元が「斬撃判定 1」になっている。
6. 「空振り時の本体リカバリー」を選ぶ。こちらは同じ判定の「接触なし」が条件になっている。
7. 左の「保存して再生」を押す。編集中の値は保存・再生成してからプレビューへ反映される。

時間軸の紫色は本体、赤色は判定、青色は表示物です。棒の中央をドラッグすると区間移動、左右端をドラッグすると区間の長さを変更します。
本体トラックの長さを変えても、参照するクリップのキー自体は伸縮しません。速く再生したい場合は再生速度を変更します。

### 接触と空振りの比較方法

サンプルは前方約1.5の近接判定を持ち、作成時の推奨標的距離も1.5です。
接触するかは敵の移動・向き・判定対象の位置にも依存します。
確実に比較したい場合、判定1の位置や半径を編集し、一方は対象と重なる設定、もう一方は明らかに離れる設定にして、それぞれ保存して再生します。
これは実機で確認する手順であり、本章の作成時点で画面上の接触結果を確認済みという意味ではありません。

作成・保存した攻撃は本編の選択候補にもなります。制作UIだけの一時データではありません。
本編の選択にはプロファイル側の射程・優先度・クールダウンが関係します。

## 3. 本体アニメーションはどこから来るか

[BodyAnimationClip](../engine/animation/BodyAnimationClip.h)は、Animation Workbenchで作る単体オブジェクト用の変形クリップです。
保存先は通常`Resources/json/animation_clip/`で、JSONの`bodyKeys`に次の値を持ちます。

| 値 | 意味 |
| --- | --- |
| time | クリップ内の秒数 |
| translate | 本体の描画上の移動量。モデルのローカル座標 |
| rotate | 本体のローカル回転。ラジアン |
| scale | 中立姿勢を1とする各軸の倍率 |
| shear | 上側を横へずらすせん断。X・Zを使用 |
| shearPivotY | せん断で固定するローカルYの位置 |
| easingToNext | 次キーまでの補間方法 |

攻撃エディターはこのクリップを選び、いつ・どの速度で再生するかを設定します。クリップ内部のキー編集はWorkbenchの役割です。
サンプルは既存の`player_ability_fireball.json`を再利用しています。今回はアセット接続を確かめるための例で、敵ごとの最終モーションとして調整したものではありません。

### Blenderの骨アニメーションとの違い

今回追加したのは、オブジェクト全体の移動・回転・伸縮・せん断を扱う本体クリップです。
Blenderから取り込んだ骨のクリップを選んで、スケルトンの各関節を動かすトラックは今回追加していません。
骨の再生は既存のAnimator/Model系に別の仕組みがあります。将来接続する際は、骨クリップ名、再生状態、遷移、ボーンアタッチを別に扱う必要があります。

## 4. 攻撃の秒数とクリップの秒数

攻撃全体の時刻を`t`、本体トラックの開始を`begin`とすると、そのトラック内の時刻は次の式です。

```text
localTime = clamp(t - begin, 0, end - begin)
clipTime = clipOffset + localTime * playbackSpeed
```

開始位置0.2秒、再生速度2なら、トラック開始から0.1秒後にクリップの0.4秒を参照します。
ループを有効にした場合は、BodyAnimationClipがクリップ長を周期にして折り返します。
ループしない場合はクリップ末尾の姿勢を保持し、トラックの終了で解除します。

この方法は**絶対時刻によるサンプリング**です。前のフレームから少しずつ姿勢を積み増すのではなく、指定時刻の姿勢を毎回計算します。
同じクリップと同じ時刻なら同じサンプルになります。ただし攻撃の接触履歴やAIまで任意時刻から復元できるわけではありません。
プレビューを巻き戻す場合は、既存のプレビュー再構築・再シミュレーションの仕組みも必要です。

## 5. 入りと終わりを滑らかにつなぐ方法

トラックの始端と終端で、クリップの姿勢を中立姿勢へ混ぜます。これは**ブレンドエンベロープ**です。

```text
inWeight  = blendIn  > 0 ? clamp(localTime / blendIn, 0, 1) : 1
outWeight = blendOut > 0 ? clamp((end - t) / blendOut, 0, 1) : 1
weight = min(inWeight, outWeight)

描画用移動 = sample.translate * weight
描画用回転 = sample.rotate * weight
描画用拡縮 = 1 + (sample.scale - 1) * weight
```

拡縮を単純に`sample.scale * weight`とすると、weightが0のとき身体が潰れて消えます。拡縮の中立値は1なので、1からの差分に重みを掛けます。
入り・終わりの時間が区間全体より長い場合、最大重みが1へ届かないことがあります。これは短い区間に長いブレンドを指定した結果です。

クリップ内のキー間の回転は既存の`SlerpEuler`を使います。Euler角をQuaternionへ変換し、球面線形補間（SLERP）で姿勢を求める処理です。
一方、今回の区間端の重み付けは、サンプル済みEuler角の各成分に掛けています。このエンベロープ自体はQuaternionの最短経路ブレンドではありません。
スライムの小さな傾きには使いやすい一方、180度を跨ぐ大きな回転は別途設計が必要です。

## 6. 身体だけを動かし、物理を動かさない仕組み

[MeshRenderer](../engine/graphics/3d/MeshRenderer.cpp)には、ゲーム進行用のTransformとは別に描画用の姿勢があります。
今回はそこへ、タイムライン専用の行列レイヤーを追加しました。

行ベクトルの変換規約では、概念的な順序は次です。

```text
頂点
  × 攻撃タイムラインの姿勢
  × 通常の描画用姿勢
  × オブジェクトのワールド行列
  × ビュー・射影行列
```

タイムラインの姿勢は、せん断行列と、拡縮・回転・移動をまとめた**アフィン変換行列**から作ります。
通常の描画姿勢を後から更新しても、攻撃専用レイヤーの参照は消えません。敵用・プレイヤー用の更新関数それぞれへ毎フレーム同じ変形計算を書く必要を減らします。

### せん断の支点

せん断でXをずらす場合、モデルの高さYに比例して横へ移動します。
支点`pivotY`を固定するため、移動項へ`-pivotY * shearX`を入れます。
これにより足元を残して上半分だけ傾けるような変形を作れます。Z方向も同じ考え方です。

### 影と法線

描画用ワールド行列を組み立てる共通処理へ入れるため、その経路を利用する通常描画・特殊材質・影の行列にも姿勢が入ります。
法線にはワールド行列の逆転置を使います。これは非一様な拡縮やせん断の後にも、面に対応した法線を求めるためです。
専用描画を持つすべての敵の見た目を実機検証したという意味ではありません。

### 変わらないものと注意点

- Actorの移動座標、速度、接地処理は本体トラックから変更しません。
- 判定部品の位置は別のトラックです。本体が前へ伸びても判定が自動で伸びることはありません。
- 子オブジェクトやボーンへの追従は追加していません。目・装飾などが別オブジェクトの場合、本体変形に連動するとは限りません。
- ローカル移動量は後段のActorの拡縮・回転の影響を受けます。ワールド空間のメートル移動とは区別します。
- 既存の手続きアニメーションは基本姿勢として残ります。その上に追加姿勢を重ねます。
- プレイヤーの炎特殊攻撃では、本体トラックがある場合、旧`animation`欄の単発クリップを同時再生しないようにしています。

## 7. 中断や削除で姿勢が残らない理由

攻撃ランタイムが姿勢行列を`shared_ptr`で所有し、Rendererは`weak_ptr`で参照します。
これは**所有権を持たない弱参照**です。Rendererから攻撃の寿命を延ばしません。

1. 攻撃開始時に中立姿勢の行列を作り、Rendererへ弱参照を渡す。
2. 実行中は、その行列を現在時刻のサンプルで更新する。
3. 本体区間がないフレームは中立姿勢にする。
4. 攻撃終了・Cancel・破棄時に所有側の参照を解放する。
5. Rendererは弱参照が切れていれば、その行列を適用しない。

このため、破棄後のActorへの生ポインタを保持して「元に戻す」処理を呼ぶ必要がありません。
ただし同じRendererに複数の独立した攻撃を同時再生するレイヤーミキサーではありません。最後に接続されたタイムラインが参照先になります。
また、攻撃内で有効な本体トラックの区間が重なる場合は保存時に拒否します。

## 8. 接触分岐が見ているもの

各hitboxトラックは、その再生中に接触した対象のReplay IDを集合に保存しています。
同じ対象へ同じ判定部品から何度も通知しないための集合を、分岐条件にも使用します。

| 条件 | 成立する場合 |
| --- | --- |
| contact | 参照元が実行されて終了し、接触集合が空でない |
| no_contact | 参照元が実行されて終了し、接触集合が空 |
| track_completed | 参照元が実行されて終了した。接触の有無は問わない |

参照元が条件不成立で実行されなかった場合、三つとも成立しません。「実行したが外した」と「そもそも実行しなかった」を区別します。
プレビュー専用Actorと本編Actorの隔離チェックを通った対象だけを、この集合へ入れます。

### 接触とダメージ確定は別

この結果は物理問い合わせで対象が見つかったという意味です。
通知されたDamageEventが、無敵・ガード・ゲームルールなどで拒否される可能性はあります。
したがって「HPを削れたときだけ追撃」ではなく、「対象に判定が接触したときだけ追撃」です。
弾の後日の命中結果も、この集合には入りません。対象はこの共通シーケンスのhitbox部品です。

ダメージ確定分岐を作るなら、ダメージ処理側から受理結果と攻撃IDを返す経路が必要です。今回は追加していません。

## 9. 時間順と依存関係

分岐元は有効なhitboxで、`参照元.end <= 後続.begin`である必要があります。
判定がまだ続いている間に空振りを確定すると、その直後の接触と矛盾するためです。

ランタイムはトラック番号の並びではなく、開始時刻の昇順に処理します。
開始時刻が同じなら配列順を維持する**安定ソート**です。
分岐元は正の長さを持ち、後続の開始までに終わる制約があるので、分岐元の開始は必ず後続より前になります。
そのため、一更新で複数区間を跨いだ場合も、参照元の接触を処理してから後続を判定できます。

これは**時間方向にだけ依存する条件付きタイムライン**です。
任意のセクションへジャンプする状態機械、入力バッファ付きコンボ、ループする攻撃グラフは今回の機能ではありません。
攻撃全体の時計は進み続けます。片方の分岐が省略されても、全体時間を自動で短縮しません。

大きなdtで区間を跨ぐ場合、判定は通過した軌道を問い合わせますが、既存の移動対象の連続衝突を厳密に再現するものではありません。
瞬間的な移動や追従原点の変化も含めた制約は[部品トラックの説明](14D_攻撃の部品トラックと共有アセット.md)を参照してください。

## 10. 保存するデータ

追加したトラック項目は次のとおりです。

```json
{
  "type": "body_animation",
  "preset": "Resources/json/animation_clip/player_ability_fireball.json",
  "begin": 0.6,
  "end": 1.1,
  "condition": "no_contact",
  "conditionTrack": 1,
  "playbackSpeed": 0.5,
  "clipOffset": 0.3,
  "blendIn": 0.08,
  "blendOut": 0.12,
  "loop": false
}
```

これは追加項目の抜粋です。完全なファイルは[authoring_contact_combo.json](../Resources/json/attack_assets/authoring_contact_combo.json)にあります。
`conditionTrack`は0始まりの配列番号です。部品削除時は、それより後ろの番号を詰め、削除された部品への参照を未指定へ戻します。
未指定のまま分岐を保存することはできません。UIで参照元を選び直す必要があります。

古いJSONに今回の項目がなくても、速度1・開始位置0などの既定値で読み込みます。
既存の共有アセットの仕組み、敵／プレイヤーのbinding、実行中の定義のコピーは引き続き使用します。
本体クリップは攻撃開始時に読み、実行中は読み込んだキーを使います。毎フレームファイルを読み直しません。
保存時と開始時にはクリップを開けるか確認し、欠落した場合はその攻撃を部分的に開始しません。

## 12. 検証と残る範囲

自動テストでは、既存データの互換性に加え、接触分岐サンプルの読込、参照先の欠落・無効化・種別違い、分岐元が終わる前の後続開始、本体区間の重複、異常な再生値を確認します。
配列を並べ替えた参照、追加項目のJSON往復、実際のBodyAnimationClipのループと末尾サンプルも対象です。
これらはGPU描画・実接触・画面操作を通した検証ではありません。

2026-10-07の実行結果:

- Development x64のビルド成功。
- 続けて実行した増分ビルドも成功。C++の再コンパイルは発生せず、約2.6秒で完了。
- AttackSequenceTestsの既存項目と本体・分岐アセットの追加項目が成功。
- 変更したソースと追加データのUTF-8、新章のファイルリンクを検査。
- 実際のUI操作、接触／空振りの見た目、HP変化、子パーツとの見た目の整合は未確認。

次に残るのは、骨アニメーションの接続、親子／ボーンアタッチ、ギズモ、入力やダメージ確定によるセクション遷移、既存攻撃の移行です。
今回の変更で表現できる組み合わせは増えましたが、あらゆる新攻撃をコードなしで作れる状態にはまだ達していません。
新しい仕組みを一度共通部品として実装すれば、その組み合わせや数値をエディターで増やせる、という段階です。
