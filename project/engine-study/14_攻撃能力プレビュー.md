# 攻撃・能力プレビューの内部

[目次](00_目次と読み方.md)へ。[`EnemyAttackPreviewWindow`](../engine/utility/SystemDebug/editor/windows/EnemyAttackPreviewWindow.cpp) は、攻撃やコピー能力の動きを専用のシーン条件で繰り返し確認するための画面。VFX Preview Stage が主に効果の形を見るのに対し、この画面は Player や攻撃定義の動きと効果の発火を一緒に見る。

## 表示されるまでの処理

1. 現在の Scene がプレビュー Object を置けるか確認する。
2. プレビュー対象と、必要な Player / Enemy / ダミーを作る。
3. 攻撃定義や能力の種類を選ぶ。
4. 固定刻み `kFixedPreviewStep` で対象を Update し、時刻ごとの状態を `TimelineSample` に記録する。
5. [`EnemyAttackPreviewWindow.Timeline.cpp`](../engine/utility/SystemDebug/editor/windows/EnemyAttackPreviewWindow.Timeline.cpp) が時刻を横軸に変換し、攻撃区間や計測値を描く。

シークは画面上の再生ヘッドを移すだけでなく、`SeekPreview` / `RestartPreview` で状態を再構築する。1 フレーム前後のボタン、10 フレーム前後のボタンは同じ固定刻みを基準にする。タイムラインで `1F` と表示されても、実際の描画 FPS が常に 60 という意味ではない。

## 攻撃定義の時間

タイムラインは攻撃定義の `windupDuration`、`activeDuration`、`recoveryDuration`、`cooldown` を区間として描く。**予備動作**は攻撃前の構え、**攻撃**は有効時間、**硬直**は行動後の制限、**再使用待ち**は次の発動までの期間。色の帯はこれらの設定値の視覚化であり、当たり判定が実際に命中したことを示す印ではない。

別のレーンには実測サンプルから速度、高さ、変形、被弾反応、GPU 粒子システム数、CPU 粒子数、Mesh 効果数、破片数などを描く。設定値の帯と実測値のグラフを並べることで「発生を指定したのに粒子が増えない」「攻撃時間と実際の動きがずれる」を発見しやすい。見るべき次の箇所は攻撃定義の発火条件と、対応する VFX Manager への要求。

## VFX Sequencer と何が違うか

VFX Sequencer は `triggerTime` へ効果・音・カメラ命令を配置する**演出の時刻表**。攻撃プレビューは Player / Attack の更新を回し、結果として動きや粒子数を観測する**実行用の検査場**。前者でイベント位置を編集しても、後者の攻撃定義や Player 状態へ自動的に同じ値が書かれるとは限らない。問題を直すときは原因が「演出イベントの時刻」か「攻撃ロジックの状態遷移」か切り分ける。

## Play での確認が必要な理由

専用場の固定ステップは再現性を高めるが、本番シーンの地形、敵 AI、プレイヤー入力、複数の攻撃の重なり、カメラや深度の条件を全て含まない。ここで目的のタイミングへ整えた後、実際のステージで **当たり判定、敵との距離、操作感、VFX の背景との相性、処理負荷** を確認する。プレビューと Play の結果が違う場合は、対象 Scene、初期位置、更新対象、固定刻み、外部状態の順に比較する。
