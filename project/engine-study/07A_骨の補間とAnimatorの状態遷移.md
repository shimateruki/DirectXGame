# 骨の補間・GPU スキニング・Animator をつなぐ

[目次](00_目次と読み方.md) / [アニメーション概要](07_アニメーション演出リプレイ.md)

## 1. 三つの階層を分けて読む

「歩くアニメーションを再生する」には、どのクリップを選ぶか、現在時刻の骨姿勢をどう求めるか、その骨で頂点をどう変形するか、という三つの処理がある。

| 階層 | このコードの入口 | 出力 |
| --- | --- | --- |
| 状態を選ぶ | [AnimatorControllerRuntime](../engine/animation/AnimatorController.cpp) | 状態名、再生時間、遷移重み、イベント |
| 姿勢を作る | [Model.Animation](../engine/graphics/3d/model/Model.Animation.cpp)、[Model.Skeleton](../engine/graphics/3d/model/Model.Skeleton.cpp) | 各 Joint の行列 |
| 頂点を変形する | [Model](../engine/graphics/3d/model/Model.cpp)、[Skinning.CS](../Resources/shader/object3d/Skinning.CS.hlsl) | 変形済み頂点 |

エディターの状態遷移線を変えても、クリップ内部の肘の角度は直接変わらない。骨のキーを直しても、ゲーム側から状態を選ぶ条件が成立しなければその動きには切り替わらない。

## 2. キー間の時刻を割合にする

Model の `CalculateValue` は時刻順のキーを線形探索し、時刻が入る区間を探す。二つの時刻を t0、t1 とすると割合は `(time - t0) / (t1 - t0)` になる。

位置が時刻 0.2 で X=1、時刻 0.6 で X=5 なら、時刻 0.3 の割合は 0.25、位置は `1 + (5 - 1) * 0.25 = 2`。これが Lerp（線形補間）である。スケールにも同じ方式を使う。

回転のキーは Quaternion として `Math::Slerp` に渡す。単純な Euler 角の成分補間では角度の折り返しや回転順に影響されるため、回転として補間する。ただしこれだけで姿勢が常に自然になるわけではなく、キー配置や関節の可動域は別問題である。

最初より前は最初の値、最後より後は最後の値を返す。Model の Vector3 キーが空ならゼロ、Quaternion キーが空なら単位回転である。空の scale カーブでも自動的に `(1,1,1)` を返すわけではない。アセットのチャンネル欠落と呼出側の補完を確認すべき理由になる。

## 3. ローカル姿勢から骨階層全体へ

Joint は親の番号と自身の localMatrix を持つ。`CreateJoint` は親を配列へ追加してから子を再帰追加する。そのため配列順に更新すれば、子を処理する時点で親の結果ができている。

この実装の行列の掛け順は次の通り。

```text
localMatrix = Scale × Rotation × Translation
skeletonSpaceMatrix = localMatrix × parent.skeletonSpaceMatrix
```

根には親がないので skeletonSpaceMatrix は localMatrix と同じ。例えば手首のローカル姿勢を変えなくても、肘や肩が回転すれば手首の骨空間位置は変わる。親子の積が上位の変形を伝えるためである。

列ベクトルで説明する教材では掛け順が逆に見えることがある。式を移植する際は、このコードの `mul(position, matrix)` と整合させる。行列のメモリ配置と、数学上どちらからベクトルを掛けるかも同じ概念ではない。

## 4. inverse bind pose が必要な理由

`UpdateBoneBuffer` の骨パレットは `inverseBindPoseMatrix × joint.skeletonSpaceMatrix` を使う。Bind Pose はモデル作成時の基準姿勢である。

頂点は最初から基準姿勢に合わせて配置されている。現在の骨行列だけを掛けると、基準姿勢の位置・回転を二重に加えることになる。まず基準姿勢の変換を逆に戻し、それから現在姿勢へ運ぶ。この二段階を一枚の行列にしたものが、頂点に使うスキニング行列である。

基準姿勢と現在姿勢が同じなら両者が打ち消し合い、元の頂点がそのまま出ることが期待される。ただしモデルの座標変換やルート構造も含めて整合している必要がある。

## 5. Linear Blend Skinning

現行 Compute Shader の一頂点には四つの骨番号と四つの重みがある。行列を重み付きで足し、その行列で位置を変換する。

```text
M = w0 M0 + w1 M1 + w2 M2 + w3 M3
p' = p M
```

これが Linear Blend Skinning（LBS）。肘の近くの頂点を上腕 0.3、前腕 0.7 とすれば、両骨の変形結果をその割合で混ぜる。どちらか一方だけへ所属させると関節が割れたり硬く曲がったりするため、境界を滑らかにする。

Shader は重みの絶対値の和で割り、骨番号を上限へ制限する。通常の非負の重みなら合計を 1 にそろえる処理になる。負値を正しい重みに修復する設計ではないので、不正データを何でも救済するとは考えない。

法線と接線は合成行列の 3×3 部分を掛け、長さが十分なら正規化する。任意の非一様スケールに対して逆転置行列を別途評価する式ではない。LBS 自体にも強いねじれで体積が痩せるなどの性質がある。Dual Quaternion Skinning は比較対象となる別方式であり、ここで採用されている方式ではない。

## 6. Compute Shader から描画へ

`Skinning.CS.hlsl` は一グループ 64 スレッド、一スレッド一頂点。端数のスレッドは頂点数との比較で終了する。入力頂点と骨行列は SRV、出力頂点は UAV である。

```text
CPU：時刻・骨姿勢を決める
  ↓ 骨パレット
GPU Compute：各頂点を変形
  ↓ 変形済み頂点バッファ
GPU Graphics：画面へ投影して描く
```

出力の boneWeights と boneIndices はゼロにする。後続の Graphics Pass に「変形済み」を伝え、同じ骨変形をもう一度掛けないためである。Compute に対応する条件を満たさない場合の経路もあるので、モデル全てがこの処理を通るとは扱わない。

Model の `Update(bool force)` はフレーム番号を見て同じフレームの重複更新を抑え、骨階層とボーンバッファを更新する。この関数自体が dt を加算してクリップ時間を進めるわけではない。再生時間を決める側と姿勢の反映側を分けて読む。

## 7. クロスフェードは二つの時刻を持つ

`ApplyBlendedAnimation` は元クリップを fromTime、新クリップを toTime で評価し、その二姿勢を blendWeight で補間する。各骨の移動とスケールは Lerp、回転は Slerp。

例えば歩きの途中から走りへ 0.2 秒で切り替えるなら、切替中も歩きと走りの時間がそれぞれ進み、その混合率が 0 から 1 へ変わる。単に前の姿勢を固定して新しい姿勢へ近づける方式とは異なる。

現行ブレンドは、元側チャンネルがないと現在の Joint 値、新側がないと元側サンプルを代替にする。両側に対象 Joint がなければその Joint を変更しない。欠落チャンネルの扱いは単独クリップの `CalculateValue` と同一ではない。

## 8. Animator は有限状態機械

`AnimatorControllerAsset` は状態と遷移条件を保存する定義、`AnimatorControllerRuntime` は現在状態・時間・パラメーター・未消費イベントを持つ実行状態である。これは有限状態機械（Finite State Machine）の構成である。

自動遷移は現在状態専用を先に調べ、その後に Any State を調べる。同じ優先度では定義順。条件はすべて成立する必要があり、exitTime がある場合は時間条件も満たす。条件も exitTime もない遷移を毎フレーム自動発火させない。自分自身への自動遷移も除外する。

Trigger は持続する bool と使い方が異なる。遷移先が有効なことを確認してから、成立した遷移の Trigger を消費する。存在しない行き先によって入力だけ消えてしまわないためである。

## 9. イベントは「時刻が等しい」ではなく「区間を通った」で発火

イベントを `time == 0.3` のように判定すると、0.29 から 0.31 へ進んだフレームで取りこぼす。`CollectCrossedEvents` は概ね `(previousTime, rawNewTime]` の区間に入ったイベントを拾う。前端を含めないことで、前回ちょうど発火したイベントの重複を避ける。

ループ時刻へ折り返す前の rawNewTime を使い、複数周した場合も各周のイベント時刻を調べる。例えば一秒のクリップで 0.9→1.3 と進むと、末尾のイベントと次周 0.2 のイベントを扱える。保存配列を直接並べ替えず、イベントへの参照を stable_sort して時刻順にする。同時刻同士は元の順番を保つ。

これは VFX Sequencer のイベント配列の評価順と同じとは限らない。見た目が似たタイムラインでも、各実行器の実装を個別に読む必要がある。

## 10. BodyAnimationClip と Workbench の接点

[`BodyAnimationClip::Evaluate`](../engine/animation/BodyAnimationClip.cpp) は位置・回転・スケールに加えて shear（せん断）と shearPivotY をサンプルする。ループは duration で fmod、単発は末尾で止める。区間開始キーの easingToNext で補間率を変える。

shear は平行な断面を位置に応じてずらす変形で、例えば胴体を傾けたり潰れ方を足したりする調整に関係する。骨クリップの切替だけでは得られない全体の変形を別のデータで表現できる。ただしこの Evaluate は値を返すだけであり、どのモデルへどの順番で適用するかは Workbench やゲーム側の呼出経路を確認する。

クリップを直すときはキーと補間、切替を直すときは Controller、変形が壊れるときは骨番号・重み・Bind Pose、タイミングがずれるときは再生時計と通過イベントを追う。この区分で、問題の層を絞れる。
