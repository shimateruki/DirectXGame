# 数学、座標系、時間の補間

[目次](00_目次と読み方.md)へ。エディターのスライダーが実際に何を変えるのかを、最小限の数式とコードでつなぐ。

## 座標を三段階で考える

**ローカル座標**は Object 自身を原点として測る位置。親がある場合、子のローカル座標は親の変換を受けて**ワールド座標**になる。Camera から見た**ビュー座標**へ変換し、Projection によって画面へ写す。一般形は `ローカル位置 × World × View × Projection` だが、行列とベクトルの左右の約束はエンジンの [`Math`](../engine/utility/math/Math.cpp) と HLSL の `mul` を確認する。順序を逆にすると同じ数値でも全く違う位置になる。

[`Object3d`](../engine/graphics/3d/object/Object3d.cpp) は自身と親の Transform を持ち、[`Camera`](../engine/graphics/3d/camera/Camera.cpp) は View / Projection に関わる。エディターの Gizmo で World 軸と Local 軸を切り替える意味はこの違い。親が回転していると、子の Local X 方向と画面で見る World X 方向は一致しない。

## 位置・方向・法線は同じベクトルではない

位置は平行移動の影響を受けるが、方向は受けない。法線は光の計算に使い、拡縮のある行列では位置と同じ変換だけでは向きが崩れる場合がある。[`Object3d.PS.hlsl`](../Resources/shader/object3d/Object3d.PS.hlsl) で法線と視線・光方向の内積が明るさへつながる。内積は向きが近いほど大きい。「明るさを上げたのに暗い」場合は Light 値だけでなく、法線の方向、座標系、Material の roughness / metallic を確認する。

## Quaternion と補間

3D 回転をオイラー角の各軸だけで補間すると、回転経路が不自然になったり、軸が重なる特異な姿勢で扱いづらくなる。Quaternion は回転を表す別の形式で、[`Math::Slerp`](../engine/utility/math/Math.cpp) は二つの回転間を球面上で補間する。アニメーションの回転キーは [`Model.Animation.cpp`](../engine/graphics/3d/model/Model.Animation.cpp) でこの補間を使う。位置・スケールには線形補間など別の方法を使うので、全キーが Slerp ではない。

`t=0` は開始、`t=1` は終了という正規化時間を考える。線形補間は `a + (b-a)×t`。Easing は `t` 自体を曲線へ変換し、同じ開始・終了値でも加速・減速の見た目を作る。[`Easing`](../engine/utility/math/Easing.cpp) と [`AnimationInterpolation`](../engine/utility/math/AnimationInterpolation.h) を読むと、UI の「Ease In / Out」が値の変化率をどう変えるか分かる。[`VFXAuthoringEditor`](../engine/utility/SystemDebug/editor/vfx/VFXAuthoringEditor.h) は曲線キーごとの補間方法を UI で選べる。

## 秒、フレーム、固定刻み

速度 `m/s` に経過秒 `deltaTime` を掛ければその更新で進む距離 `m` になる。`deltaTime` を掛け忘れると FPS に応じて移動量が変わる。逆に既に「1 更新当たりの量」として設計された値へ重ねて掛けると遅くなる。単位は変数名だけでは確定しないので、設定ファイルと実際の積算式を見る。

粒子プレビューのシークでは CPU 側を `1/60` 秒ずつ進める実装が多い。ただし GPU 粒子の Update は経過時間を蓄積するだけで、Draw を挟まない 60 回の Update は GPU 物理の 60 回更新とは異なる。ゲーム本編の固定更新、プレビューの CPU 時計、GPU Dispatch、表示 FPS を別々に追う必要がある。[GPU の詳細章](04A_GPUパーティクルのメモリと計算.md)でこの違いを扱う。

## データを読むときの単位表

| 値 | 確認すること |
| --- | --- |
| 時刻・duration | 秒か、フレーム数か、0～1 の正規化時間か。 |
| 角度 | 度か、ラジアンか。Camera の FOV と三角関数の入口を確認。 |
| 位置 | Local か World か。画面座標なら Viewport の原点と倍率も必要。 |
| 色 | sRGB の入力か、線形空間の計算値か。HDR 値と 0～1 の色を混同しない。 |
| 法線 | Model 空間か World 空間か。法線マップなら接線空間からの変換がある。 |

この表は一律の規約ではなく、コードを読むときの質問表。値ごとの実際の単位は該当する設定構造体と変換式で確定する。
