# ゲーム実行時の下位システム

詳細解説：[衝突と A*](08A_衝突判定とAStar経路探索.md) / [時計・入力・音声](08B_時計と入力と音声の寿命.md)。

[目次](00_目次と読み方.md)へ。エディターで設定した値が Play 中にどう使われるかを、入力から描画まで追う。ゲーム固有の Player・Enemy の判断処理は `game/` 側にあるため、この章は共通のエンジン機能を中心にする。

## Scene Manager とフレーム更新

[`SceneManager`](../engine/system/scene/SceneManager.cpp) は現在のシーン、切替、Play 状態を管理する。毎フレーム何がいつ呼ばれるかは [`Game`](../engine/core/Game.cpp) と [`Framework`](../engine/core/Framework.cpp) が入口。固定更新は「1 回の描画につき必ず 1 回」ではない。経過時間に応じて必要な回数を実行し、描画とは別の周期でシミュレーションを進める。入力を読む時点、衝突を処理する時点、描画用 Transform を更新する時点がずれると、1 フレームの見た目と物理状態が食い違う。

Scene JSON の値は読込後に Object や Component の実体へ反映される。エディターの保存値そのものが毎フレーム描画されているわけではない。[保存章](06_シーン編集とデータ保存.md)と合わせて、ファイル → ロード → メモリ上の設定 → Update → Draw の流れを追う。

## 入力：現在状態と変化

[`InputManager`](../engine/system/input/InputManager.cpp) はキーボード・マウス・ゲームパッドの状態を更新する。一般に `押している` は現フレーム状態、`押した瞬間` は前フレームとの差、`離した瞬間` は逆の差で判定する。用途を間違えると、1 回だけ実行したいジャンプや決定が押している間ずっと発火する。実際の API 名・デバイスごとの差は [`InputManager.h`](../engine/system/input/InputManager.h)で確認する。

エディターとゲームが同じ入力を受け取る場合、ImGui がキーボードやマウスを操作中か、Game View がフォーカスされているかが重要。`Game::Update` からゲーム側へ入力が渡る条件と、エディター側のショートカット条件を読む。入力値の単位は軸なら概ね正規化値、マウス移動なら画面上の移動量など、API ごとに異なるので変換場所を確認する。

## 衝突：候補探しと正確な判定

[`CollisionManager`](../engine/system/collision/CollisionManager.cpp) は衝突候補を管理する。空間グリッドを使って近い相手を探す**広域判定**と、形状同士が実際に重なるか調べる**詳細判定**は別段階。全 Object の全組合せを毎回調べるより候補数を減らせる。静的・動的な対象の扱い、Ray、Overlap、Cast の入口もここにある。形状別の計算は [`CollisionConfig`](../engine/system/collision/CollisionConfig.cpp)を参照する。

Ray は始点と方向に沿った交差、Overlap は現在位置での重なり、Cast は形状を動かしたときの途中の交差を調べる。用途が違うため、カメラの視線判定を単純な現在位置 Overlap へ置き換えると壁越しの対象を拾う。レイヤーや有効フラグで候補を除いているかも確認する。衝突はゲームの意思決定まで自動で行わず、結果を受けた Player / Enemy / Gimmick が反応を決める。

## ナビゲーション：通行情報と移動

[`NavGrid`](../engine/system/navigation/NavGrid.cpp) は移動可能な空間をグリッドとして扱う。[`NavAgentComponent`](../engine/component/NavAgentComponent.cpp) は Object 側の移動用構成要素。ナビゲーションが答えるのは主に「どこを通れるか・どの経路を選ぶか」であり、足元の衝突解決やアニメーションそのものではない。敵が目標へ進まない場合は、目標位置、グリッド上の通行可否、経路更新、移動速度、衝突で止まっていないかを順に見る。NavMesh と決めつけず、このコードのグリッド表現を前提に読む。

## 音声：再生とイベント

[`AudioPlayer`](../engine/system/audio/AudioPlayer.cpp) は音声をロード・再生する下位経路。[`AudioSettingsWindow`](../engine/utility/SystemDebug/editor/windows/AudioSettingsWindow.cpp) は音量などを編集する側。VFX Sequencer の音イベントは「時刻が来たら音再生を指示する」層であり、デコードや再生デバイス処理そのものではない。音が鳴らないときは、イベントが発火したか、参照名から音が見つかったか、音量設定と再生チャンネルを追う。

## Component：Object へ機能を足す

[`ObjectComponent`](../engine/component/ObjectComponent.h) を基底として、[`ParticleEmitterComponent`](../engine/component/ParticleEmitterComponent.h)、[`MeshEffectComponent`](../engine/component/MeshEffectComponent.h)、[`GameplayLinkComponent`](../engine/component/GameplayLinkComponent.h)、[`PathMoverComponent`](../engine/component/PathMoverComponent.h)、[`NavAgentComponent`](../engine/component/NavAgentComponent.cpp) などがある。Component 化すると Object の種類を増やさずに機能を組み合わせられる。読む順番は **所有する Object → Component の設定値 → Update の呼び出し → 保存・読込**。Component を追加しただけで Serializer に登録されていなければ、次回ロード後に失われうる。

## 描画に渡る状態

[`CameraManager`](../engine/graphics/3d/camera/CameraManager.cpp) はどの視点で描くかを管理し、[`Camera`](../engine/graphics/3d/camera/Camera.cpp) は View / Projection などを提供する。[`LightManager`](../engine/graphics/3d/light/LightManager.cpp) は光源情報を描画へ渡す。[`TextureManager`](../engine/graphics/core/TextureManager.cpp) と [`ModelManager`](../engine/graphics/3d/model/ModelManager.cpp) は資産のロード・参照を管理する。CPU の Object 位置や材質が、そのまま画素ではない。[描画基盤](02_DirectX12と描画パイプライン.md)にある定数バッファ・シェーダー・描画命令を経て色になる。

## 実行時調査の順番

1. データはファイルから読み込めているか。
2. 対象 Object / Component は作成され、有効か。
3. Update が想定の周期・順番で呼ばれるか。
4. 入力、衝突、経路、イベントの条件を満たすか。
5. Draw が呼ばれ、カメラ・深度・マテリアル・ポストエフェクトで見えなくなっていないか。

この分解で、エディターの設定ミスとエンジンの実行経路の問題を分けられる。
