# ユーザーの作業を妨げない検証と実画面の提示

・調査、編集、ビルド、検証は、専用環境でバックグラウンド実行することを基本とする。
・ユーザーの作業中に、Computer Useなどで同じデスクトップのマウス・キーボードを操作したり、検証用ウィンドウを前面表示・最大化したりして作業を中断させない。
・実画面の確認には、ユーザーの入力や前面表示を必要としない、描画結果の直接保存などの方法を優先する。操作ツールを変更するだけでは、同じデスクトップへの干渉を解消したことにしない。
・CG2では、まず tests/GateEntryRuntimeProbe.h の Capture と tests/TutorialExitGuideRuntimeProbe.h の CaptureView にあるGPU描画結果の直接PNG保存を確認する。既存のデスクトップ録画機能だけを見て、バックグラウンド撮影が不可能と判断しない。取得する描画先が対象シーンの最終画像か、非アクティブ時にも描画が進むかを実行で確認する。動画化する場合は連続フレームの取得と時間間隔も確認する。
・ユーザーのデスクトップ操作が必要な場合は、バックグラウンドで進められる作業を先に済ませ、必要な理由と操作時間の目安を説明して、ユーザーが明示的に操作を許可した時間だけ使用する。
・見た目、カメラ、UI、パーティクル、エフェクトなどを変更した場合は、可能な範囲で専用環境の実際のゲーム画面を確認し、ユーザーが自分で起動しなくても確認できる動画や画像を提示する。動きの評価には動画を優先する。
・現在の撮影機能がデスクトップ表示に依存していてバックグラウンド撮影できない場合は、その制約と必要な改良を報告する。無断で前面操作を再開しない。
・実画面、静的検証、ビルド結果、参考図やモックを区別し、確認できなかった動作や見た目を検証済みと報告しない。
・ユーザーの実行中EXE、シーンJSON、設定、セーブ、他チャットの作業を保持する。検証用環境と撮影データの保存先を分離し、完了後は必要な証拠を残して不要な専用環境を片付ける。
